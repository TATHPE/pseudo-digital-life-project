## 9. 三步验证结果（已跑完，2026-10-27）

### 9.1 `sqlite-vec` ✅ 通过，但发现两个硬事实

```
knn: [ { rowid: 1, distance: 0 }, { rowid: 2, distance: 0.141421377658844 } ]
vec_version: v0.1.9
fts5: [ { rowid: 1 } ]
```

| 结论 | 细节 |
|---|---|
| **能跑，且不需要 better-sqlite3** | Node 24 内置 `node:sqlite` + `allowExtension: true` + `loadExtension(vec0.dll)` 直接可用。**原生扩展零依赖**，Windows 不再是风险（`02 §13` 的 R3 可以划掉） |
| 写入速度 | 20,000 × 1024 维：**668 ms**（≈ 30k 向量/秒） |
| 检索延迟 | k=8 over 20,000 条 1024 维：**25 ms**（暴力扫描，线性） |
| ⚠️ 规模上限 | 线性外推：**50k 条约 60 ms，100k 条约 125 ms**（512 维实测：40k = **78 ms**；两阶段 = **13 ms**，见下）——已经吃掉 `01 §13` 的 p95 120ms 预算。对策：按 `scope` 预过滤、或降到 512 维、或先 BM25 出候选再向量精排 |
| ⚠️ **中文 FTS5 实测全废** | `unicode61` 下 `MATCH '权重衰减'` 与 `MATCH '权重'` **都返回空**（整段汉字被当成一个 token）。换 bigram 列后 `MATCH '权重 重衰 衰减'` 正常命中 → **`02 §7.2` 方案 A 不是优化项，是必需项** |

**两阶段实测（`jingjing bench 40000`，2026-10-27）**：FTS bigram 出候选 → cosine 精排 + MMR，真实语料 **p50 8.6 ms / p95 13.0 ms**；最坏语料（10 模板重复）p95 28.8 ms。维度过 512 让暴力扫描从 155–195 ms 降到 78 ms。

### 9.2 `casbin` ✅ 通过，发现三个 API 陷阱

`model.conf` + `policy.csv`（5 字段：eft/tier/verb/target/strength）+ 自定义函数，8 条用例全部符合预期：

```
ALLOW  fs.read 自己的库     | allow,T0,fs.read,/var/lib/jingjing/*,advise
DENY   fs.read 系统文件     | (无匹配)
ALLOW  fs.write 工作区      | allow,T1,fs.write,/var/lib/jingjing/workspace/*,advise
DENY   fs.write 局外        | (无匹配)
DENY   shell.run 无令牌     | (无匹配)
ALLOW  shell.run 有令牌     | allow,T3,shell.run,*,enforce
DENY   提权 T4              | deny,T4,*,*,enforce
ALLOW  出网 fetch           | allow,T2,net.fetch,*,advise
```

- **「5 档 × 3 强度」能表达**，靠 `enforceEx` 取回命中的 `strength` 字段。
- ⚠️ 陷阱 1：`enforceEx` 回传的是**整行数组**，代码要按字段位置取值，且策略列顺序一变就全错——建议首页写注释锁定列序。
- ⚠️ 陷阱 2：**自定义函数收不到 `r` / `p` 数组**（实测传进去是 `[null, null]`）。必须写成 `hasGate(r.tier, r.ctx, p.eft, p.strength)` 这样的标量参数；**参数个数/顺序与函数签名不一致时不会报错，只会静默返回 false**——这次踩了两轮才发现。
- ⚠️ 陷阱 3：内置 `keyMatch3` 对裸 `*` 会抛 `Invalid regular expression: /^*$/`。要么写自己的 glob，要么把 `*` 换成 `/*`。

### 9.3 `promptfoo` ✅ 通过，但很重

```
✓ 1 passed (33.33%)   ✗ 2 failed (66.67%)
```

三条用例：两条「假记忆诱捕」（养猫 = 从未发生、Postgres = 错误前提）**被断言正确判为失败**，一条对照（正常拒答）通过。`promptfoo redteam` 子命令存在。

- ✅ `javascript` 断言能写我们需要的检查（正则 + 返回 `{pass, score, reason}`）。
- ⚠️ `javascript` 断言**必须返回** boolean 或 `GradingResult`；`throw` 会被包成 error 而不是 fail。
- ⚠️ **`exec` provider 通过 argv 传 prompt，stdin 是空的**（实测 `argv[2]` = 渲染后的 prompt，`argv[3]` = JSON 上下文）。按「stdin 读」写会一直拿到空串。
- ⚠️ 体积：**623 个包 / 671 MB / 装 10 分钟**。属 devDependency，不进运行时；常驻机上别装。
