## 2. 一页纸结论

**这 9 篇基本覆盖了鲸鲸"记忆动力学"的全部技术面，且有 3 篇（FadeMem / Oblivion / DISCERN）几乎就是把 `01` 的公式重写了一遍。** 好消息是方向对；坏消息是我在两处写了缺陷，以及一条本来以为可以省掉的工作其实省不掉。

三条最重要的发现：

1. **纯指数衰减是错的，应该用拉伸指数（Weibull）**。FadeMem 的记忆强度是 `v(t)=v(0)·exp(−λ(t−τ)^β)`，`β<1` 时前段陡、后段长尾——这与真实遗忘曲线一致，而我们的 `exp(−λΔd)` 会"前段太慢、后段太快"。**已改**（`01 §4.1`）。
2. **单阈值会震荡，必须用双阈值滞后**。FadeMem 用 `θ_promote=0.7 > θ_demote=0.3`。我们的 `0.35 / 0.15` 两个独立边界会让权重刚好在 0.35 附近的记忆**每晚反复升降**，而 `stage` 变化会写进审计、影响注入。这是个真 bug。**已改**（`01 §5`）。
3. **"召回"其实已经被解决了，"resolution"（指代、时效、该不该答）才是难点**。DISCERN 在 ENT-310 上实测：8 个系统在 retention/currency 上都有 0.93–0.98，饱和；真正的差距在 abstention（F1 0.924 vs 最强基线 0.802）与实体消解（0.800 vs 基线 <0.40）上。这直接说明：`02` 里我们花了大量篇幅调 recall@5，而**应该把权重挪到冲突消解 + 拒绝回答**。**已改评估口径**（`01 §13`、`02 §11`）。

另外两条对我们这种"单用户长时程"场景的提醒：

- **ZenBrain 的 "cooperative masking"**：在轻度负载下单机制消融的效果与 0 无法区分；把 decay 从 0.15/day 提到 0.25/day，显著机制从 1/15 变成 9/15。**含义**：我们的 eval 如果在"温和"条件下跑，会误判"衰减机制没用"。**已加压力测试要求**（`01 §13`）。
- **RecMem 的预算数据**：只在检测到"复现（recurrence）"时才触发 LLM 固化，token 消耗降低最多 **7.8×**。这验证了 `01 §9` 夜间批处理 + 只在聚类足够大时才融并的做法，并给出量化预期。

## 3. 逐篇摘要

### 3.1 FadeMem（阿里国际 + 北大）— 最贴近 `01` 的一篇

**问题**：Agent 记忆只有二元策略（全留或全丢），导致上下文边界灾难性遗忘或信息过载。

**机制**：
- 双层记忆（LTM / LML），每层独立衰减率
- 记忆强度 `v_i(t) = v_i(0)·exp(−λ_i·(t−τ_i)^β_i)`（重构自其半衰期式 `t½=(ln2/λ)^{1/β}`）
- **重要度调制衰减率**：`λ_i = λ_base·exp(−μ·I_i(t))`——重要性进的是**速率**，不是初始值
- 半衰期：`β=0.8`（LML）时 `λ_base=0.1` 给出 ≈11.25 天；`β=1.2`（LTM）更长
- **双阈值滞后**：`θ_promote=0.7`、`θ_demote=0.3`（原文明确："introduces hysteresis that prevents oscillation"）
- 剪枝：强度 < `ε_prune`，或 dormant 超过 `T_max` 天
- 冲突：语义相似 `sim>θ_sim` 的候选交给 LLM 判策略；聚类超阈值时 LLM 融合，`v_fused(0)=max v_i(t)+ε·var({v_i})`

**数字**：Multi-SessionChat / LoCoMo / LTI-Bench 上**存储降 45%**，多跳推理与检索不降。

**对鲸鲸的用法**：直接借 `β`、`λ` 的重要性调制、滞后阈值、`ε_prune`。**不借**它的"LLM 判冲突"作为主路径（我们坚持确定性优先，LLM 只在模糊分支）；**谨慎借**融合（见 §4.3）。

### 3.2 Oblivion（NEC Labs）— 读/写分离的工程实现

**问题**："always-on" 检索 + 扁平存储 → 干扰与延迟随历史增长。

**机制**：四个模块，**读路径 = 激活（Activation），写路径 = 强化（Reinforcement）**：
- `Decayer`：按衰减更新可及性
- `Activator`：查询时决定"要不要检索、检索多少"
- `Recognizer`：识别记忆的簇与元指令（`π_in`："这个领域的问题该怎么处理"）
- `Manager`：调度
- **双信号门控 + 自适应阈值**：第一轮 `OR`（偏召回），后续轮次 `AND`（偏精确），避免缓冲区已满还重复检索

**对鲸鲸的用法**：`Activator` 这个"检索前先判断要不要检索"的角色我们完全缺失——目前 `search` 是查询进来就无脑跑。多轮对话里这会造成重复注入。**建议采纳为 P2 优化项**（清单 #7）。`OR→AND` 的自适应门控可以套在"本轮要不要注入第 3..8 条"上。

### 3.3 DISCERN（Amazon）— 最重要的"反向证据"

**问题**：企业 agent 跨数十会话累积的记忆会互相矛盾、被取代、相似实体在嵌入空间里糊在一起。作者直接说：**这不是检索问题**。

**机制**：
- 写时"保守"：构建**严格增量**的**双时间**溯源图，**永不合并易混实体**，**永不丢弃被取代的旧值**
- 读时"解析"：零 LLM 的工具面在图上导航，**必须落在四个门控终止动作之一**（回答 / 澄清 / 放弃 / 索取证据）
- `EarnedAbstainGate`：**只在"证明了不存在"时**才放弃；`DeclineRouter` 把"有可混淆候选"路由到 CLARIFY，"一个都没有"路由到 ABSTAIN
- 渲染器**强制每个回答引用证据**

**数字**（ENT-310，310 条查询 = 210 可答 + 100 不可答）：abstention F1 **0.924**（最强基线 ≤0.802）；实体消解 0.800（基线 <0.40）；retention/currency 各系统 0.93–0.98（饱和）。

**对鲸鲸的用法**：三条直接落地——
1. 我们 `02 §8.2` 里"相似度 >0.92 → supersede/合并"**与它的结论相反**。结论应该是：**不合并、不覆盖，只加边**。已改成"写入只增不改 + 读时解析"。
2. `confidence:none` 升级成**四态**：`answer / clarify / abstain / need_evidence`。我们只有"答"和"不知道"，缺 `clarify`——而"你是不是指 X？"恰恰是最像人的反应。
3. 我们的"假记忆诱捕" eval 直接对标它的 abstention F1 口径。

### 3.4 ZenBrain — 15 个机制的架构提案，价值在方法论

**主张**：7 层、15 机制（Two-Factor 突触固化、Simulation-Selection 睡眠环、NeuromodulatorEngine、**ReconsolidationEngine**、TripleCopyMemory、PriorityMap、StabilityProtector、MetacognitiveMonitor…），由单一 MemoryCoordinator 统管。作者自述：**被调查的系统里没有一个整合了超过两个机制**。

**最有价值的一句**（也是对我们最不利的一句）：

> "cooperative masking"：在协同冗余的系统里，**轻度负载下的单机制消融，对真正承重的机制也会报出与 0 无法区分的贡献**。同一 15 组消融，decay 0.15/day 时只有 1/15 显著；0.25/day 时 9/15 显著，其中 5 个从 0% 掉到 −89%。机制没变，只有压力变了。

**对鲸鲸的用法**：这不是"该抄的机制"，而是**评估方法学警告**。我们的 eval 必须至少跑两档衰减压力 + 一个长时程（≥30 天模拟）。否则会得出"衰减没用，删了吧"的错误结论。已写入 `01 §13`。

### 3.5 RecMem（CUHK + 华为）— 什么时候才值得调用 LLM

**机制**：先用轻量 embedding 把原始交互放进"潜意识缓冲区"，**只有当新交互能在里面找到足够多语义相似/相关的邻居（复现）时，才用 LLM 做固化**，把 episodic 提炼成 semantic。

**数字**：LoCoMo 上记忆构建的 token 消耗降低最多 **7.8×**；默认 `k_sub=10`、`k_epi=5`；`θ` 从 5 提到 6 时性能明显下降（说明阈值不能太贪）。

**对鲸鲸的用法**：把 `01 §9` 的"夜里无差别抽取"改成"**只在出现复现时固化**"——这既省算力（本机 8GB 尤其需要），也更像人（同一件事第一次不记，反复出现才沉淀）。建议采纳（清单 #5）。

### 3.6 FSFM（中国移动九天）— 遗忘的分类学

**贡献**：把遗忘机制分成四类——**被动衰减 / 主动删除 / 安全触发 / 自适应强化**，并给出实现架构与安全维度评估。

**数字**：访问效率 +8.49%，信噪比 +29.2%，**安全风险 100% 消除**。

**对鲸鲸的用法**：`安全触发型遗忘`是我们只有 `taint=external` 没有完整覆盖的一类——需要"检测到恶意/隐私内容 → 主动遗忘"这条通路。它与 `04` 的 T4（禁止提权/凭据访问）不是一回事：T4 阻止**读取**，安全遗忘是**删掉已经进来的**。建议作为 P3 增补项（清单 #9）。

### 3.7 TSUBASA（Michigan）— 人格与偏好长时程演化

**机制**：演化记忆 + 自学习 + **上下文蒸馏**（把记忆内化进模型，而不是每次都 RAG）；结论强调"提取出的观察信息密度高""记忆内化有效"，但**显式 RAG 支撑仍然必要**。

**对鲸鲸的用法**：两件事——
1. "内化 + RAG 并存"支持我们 `00 §5` 的 `persona/core.md`（内化风格，few-shot）与记忆装配（RAG）分离的做法。
2. 它的"演化记忆"针对的是**用户偏好漂移**，正是我们 `self_state.closeness` 和 `preference_soft` 该做的事，可作为 P4 画像复核阶段的参考实现（清单 #11）。

### 3.8 Sleep's contribution to memory formation（Physiol Rev 2026）— `01 §9` 的理论根据

120 页综述。对工程有直接意义的四点：

1. **巩固是主动过程**：新记忆初始不稳定，通过离线再激活转为长时表征；检索本身会引发**再巩固 + 可能更新**（支持我们"recall 时写回"的设计是生理上成立的，不是为了省事）。
2. **TMR（靶向记忆再激活）**：睡眠中用嗅觉/听觉线索提示，可显著提升对应记忆的保留。→ 可映射为"夜间整备时按当天出现频率给记忆打标/提升 `salience`"，即**用线索做加权复习**。
3. **SHY（突触稳态假说）**：清醒期突触总体增强，睡眠期整体下调（保留强连接、削弱的被修剪）。→ 这正好是"夜间全库重算 + 相对排序收缩"的依据，也解释了为什么**统一缩放（renormalize）比绝对阈值更稳**。
4. **抽象化/提取要点**：睡眠不只是保留细节，还产生 gist。→ 支持"从多个 episode 融出一条 semantic"，但要限制频次（见 §4.3）。

### 3.9 Engram / Synapses（Frontiers 2021）— 为什么"契约层"必须靠维护而不是存储

核心事实：engram 细胞在学习后**至少 1 个月**仍是记忆表达所必需；但突触蛋白周转很快，**持久的连接增强不可能靠"一次写入的静态结构"维持**，只能靠持续的动态更新（作者的几种候选模型都以"持续周转 + 稳定总体"为核心）。

**对鲸鲸的用法**：这条给"`contract` 层永不衰减"提供了正确解释——**它不是"存进去就不动"，而是"每次夜间整备都重新确认一遍"**。工程含义：`contract` 记忆也该进夜间任务（校验一致性、检查是否被新叙事反驳），只是**权重不变**。这是对 `01 §4.3` 的一处补强（清单 #10）。

## 4. 交叉主题与我们的位置

### 4.1 遗忘曲线的形状（4 篇一致）

`exp(−λt)` → **`exp(−λt^β)`**，`β∈[0.7,1.2]`。`β<1` 是"快速淡出 + 长尾"（日常片段），`β>1` 更接近"先稳住再淡"（重要事实）。这比我们原来一刀切的指数更贴近体验：**刚说过的话三天不淡，三个月前的事一提醒就回来**。

### 4.2 再巩固有生理依据，但"写回"的时机有争议

Sleep 综述指出检索即引发不稳定期（labilization）与更新窗口。我们的做法是**注入后立即写回**；更接近生理的是"注入 → 一个短的不稳定窗口 → 夜间统一落定"。对鲸鲸而言，**立即写回更简单且可审计**，保持现状，但在文档里标注这是工程简化。

### 4.3 融合（fusion/consolidation）是双刃

FadeMem 用 LLM 融合聚类（`v_fused = max v_i + ε·var`），Sleep 综述支持 gist 提取，RecMem 只在复现时固化。但 `01 §8.1` 我们明确"不做自动摘要压缩，因为不可逆且必然引入幻觉"。

**折中方案（建议采纳，P3+）**：融合**不删除原件**，只生成一条 `kind='gist'` 的派生记忆并建 `derived_from` 边；原件降为 `fading`。这样"压缩"可回退，符合铁律三。

### 4.4 resolution > retrieval（DISCERN）

这条如果只能记住一句，记这句。我们的 `02 §11` 评估原本 `recall@5 ≥ 0.8` 打头；现在调整为「abstain 判定」「实体/指代消解」「时效性」三条为主，recall 降为守门指标（≥0.85 即可）。

### 4.5 数据效率：本地 8GB 的硬约束下，RecMem 的 7.8× 很关键

本机能跑 4B，夜间批处理的预算是硬的。RecMem 的"先缓冲、后固化"让我们可以把 LLM 调用集中到真正反复出现的主题上。

## 6. 需要警惕的四个偏差

1. **场景不同**：9 篇里 6 篇是**多用户/多 agent/企业**场景（DISCERN 是 10 个 actor 的企业销售 agent，FadeMem 是 chat benchmark，RecMem 是 agent 任务）。鲸鲸是**单用户、长时程、人格连续**，这些论文都没有"人格不漂移"这个约束。它们的指标（token、准确率）不能直接当我们的验收。
2. **论文自身的可信度**：`ZenBrain` 是单作者的架构提案（自述"没有系统整合超过两个机制"），`TSUBASA` 与 `DISCERN` 的基准是自建合成集（ENT-310 明确是 synthetic）。数字要看趋势，不要当定论。
3. **cooperative masking 是双向的**：它既说明"别在小负载下做消融"，也说明**多机制叠加的收益可能无法单独归因**——所以我们调参时不要期待"每个参数都有独立可见收益"。
4. **公式重构风险**：如 §1 所述，`β` 的精确位置是从半衰期表达式反推的。落地时以"实现后跑两组对照（β=1 vs β=0.8），看谁的行为更像"为准，不要盲信我这里的每一个下标。
