## 2. 结论先行

1. **原文档列的项目有一半查不到。** 明确对得上的只有 4 个（pawwake、superlocalmemory、rexleimo/aios、Personal-AI-OS），`alaala`、`Tawn`、`HiveMind MCP`、`MemoryHub`、`Memora`、`ai-memory`、`Moksh AI` 在 name/description 检索里**没有对应实体**——那份清单大概率是模型生成的，不能当立项依据。
2. **“记忆基础设施”这个生态位已经被占了**（basic-memory 4.4k★、EverOS 13.7k★、mem0 67.9k★）。如果鲸鲸只是“另一个更好的记忆层”，自研 ROI 很低。
3. **但定位改成“伪数字生命”之后，参照系全变了。** 我重新看了一遍这 20 多个项目的自述，**没有任何一个**同时具备：按权重连续衰减的记忆、独立的自我状态（内感受）、无用户输入时的心跳与主动发起、可版本化的人格文件、以“不编造共同回忆”为硬约束的表达层。它们要么是**工具**（记忆层、检索层、控制平面），要么是**平台**（托管式记忆服务）。
4. **结论因此反转：** v0.1 的结论是“别自研，用 basic-memory 加个差异层”；v0.2 的结论是“**存储与检索引擎可以复用现成的，但生命机制必须自研**”——因为那部分不是技术难度问题，而是**没人把它当目标**。复用面从 80% 降到约 40%，剩下的 60% 正好是 `00`/`01` 里那些公式和流程。

## 5. 与本项目同构的三个候选（重点）

### 5.1 basic-memory（4,367★ AGPL-3.0）— 最成熟的"直接替代"

| 维度 | 事实（来自 README） |
|---|---|
| 事实源 | 纯 Markdown 文件在磁盘，Obsidian 可直接读写同一批文件 |
| 索引 | **SQLite（默认）** 或 Postgres；语义向量可选 Milvus |
| 检索 | 全文 + 向量混合排序；**FastEmbed 本地嵌入**（ONNX，无需 Ollama/API Key）；可选本地 cross-encoder 重排 |
| 协议 | MCP（stdio/https），工具带 behavior hints（read-only / destructive / idempotent） |
| 云 | 有托管版（Neon Postgres + S3），但**本地版完全等价**，同一套 Markdown |
| 短板 | AGPL-3.0（商用需注意）；英文语境优化；记忆治理（冲突/遗忘/隐私分级）偏弱；无"只给云端看 shareable 子集"的概念 |

**对你的意义**：它已经实现了你 P0+P1+P2 的大部分。若接受 AGPL，**自研必要性下降一个数量级**。

### 5.2 EverOS（13,658★）— 架构同构度最高的"参考实现"

README 自述：*"Markdown source of truth + 本地 SQLite + LanceDB 索引，不需要 MongoDB / Elasticsearch / Redis"*；提供 markdown 持久化、级联索引、关键词检索，以及可选的 embedding 混合检索、reflection、skill extraction；`uvx everos-mcp` 直接接 Claude Code / Cursor / Codex。

这与 `02 §3` 的分层**几乎一一对应**（Markdown 事实源 → 本地索引 → 混合检索 → MCP）。差别在于：
- 它的记忆演进（merge episode clusters、profiles、skills）依赖 **外部模型**（默认 OpenRouter 的 `gpt-4.1-mini`），不是本地 Ollama
- 它的重心在"用户画像 + 技能沉淀"，你的重心在"项目事实 + 决策可追溯"

**对你的意义**：当作**架构对照物**读一遍 `docs/how-memory-works.md`（Markdown/SQLite/LanceDB/recall 流程），比你从零设计快。同时它验证了一个判断：**LanceDB 是 SQLite 向量扩展遇到麻烦时的正解**（这与 `02 §3.1` 的备选一致）。

### 5.3 superlocalmemory（260★ AGPL-3.0）— 治理诉求最接近

Mode A：core remember/recall **不发起任何模型提供方调用**——无 API Key、无云账号、无 Docker。召回还带"诚实层"：答案不在库里就回 *"That isn't in SuperLocalMemory."*，而不是硬编。

这几乎就是 `00 §11`「宁可说不知道」原则的工业实现，也是 `02 §7.1` "阈值低于 0.25 返回 `confidence:none`" 的同款思路。

## 7. 自研价值域的重新划分（v0.2）

定位从「记忆基础设施」改成「伪数字生命」后，自研边界变成一条清晰的切线。

### 7.1 可以复用（不自己写）

| 模块 | 现成方案 | 为什么不自研 |
|---|---|---|
| Markdown → 分块 → 索引 → 混合检索 | basic-memory 的引擎 / EverOS 的 recall 流程 | 纯工程题，别人已经做了很久，自研只是重造轮子 |
| 本地 embedding | FastEmbed(ONNX) 或 Ollama bge-m3 | 成熟实现，与业务无关 |
| MCP 协议层 | `@modelcontextprotocol/sdk` | 标准实现，无差异空间 |
| 文档转换 | markitdown（已就绪） | 同上 |

### 7.2 必须自研（生态里的空白）

1. **权重衰减与再巩固引擎**（`01 §4`）。没有任何项目把记忆做成连续量；它们的 "forget" 都是删除或按时间排序。这是鲸鲸的核心差异点，也是投入产出比最高的部分（`decay.ts` 约 40 行纯函数 + 测试）。
2. **叙事 / 契约双层不变量**（`00 §2`）。现有系统的记忆是平的，而「会腐烂的」与「不能腐烂的」混在一起，正是数字人不可靠的根源。
3. **自我状态与心跳**（`01 §8–10`）。所有项目都是**被动响应**（连 Letta 也是）。无输入时也运转、且有节制地主动，是「生命」与「工具」的分界线。
4. **防编造的表达层**（`00 §11`）。最有价值的工程细节：`cite` 约束 + 空记忆硬指令 + 输出后置检查 + 诱捕 eval。现有项目的 README 里没有一个提到这个问题，而它对体验的破坏力最大。
5. **人格外置与可版本化**（`00 §5`）。为了「换模型不换人」。
6. **中文场景**：分词（二元组方案）、`标题 › 章节路径 + 正文` 的 embedding 输入格式。

### 7.3 一句话

> **「像人的部分」得自己写，「像工具的部分」能用就用。** 前者恰好是开源社区不感兴趣的部分（不好度量、不好卖），后者恰好是已经卷到极致的那部分。

## 11. 一个非项目的样本：某 QQ 机器人的「记忆浮现」踩坑记录（2026-10-30 读）

来源：用户转的一篇实践文（作者做了一个跑在自己电脑上的 QQ 机器人，"她"有角色设定、长期记忆、会画画发语音）。
它不开源、没评测、只有一个作者，**但它是目前看到的、唯一把"浮现"这条线迭代到底的样本**——
五版，每一版都是被使用者（"她"）一句话打回重做的。

### 11.1 它把我们没做的那一层做完了

| 它的机制 | 它为什么这么做 | 鲸鲸现状（2026-10-30 实核） |
|---|---|---|
| **原话层**（每条记忆存 1–3 句原话，浮现时先给原话） | 想起"奶奶生日"时，先浮出来的是那句「我奶奶生日为什么不提醒了」，而不是抽象条目 | ❌ `source_ref` 存的是抽取器的 reason，不是用户原句 |
| **关系（link）参与一跳召回** | 想起来往往是因为“刚才那句说到了别的，顺着一根线走过去” | ⚠️ `memory_links` 有表，只在夜间写 `supersedes`/`derived_from`，**零处读取** |
| **关系必须写“为什么连”（≤ 20 字）** | “线接上了得有个说法，说不出来的线本来就不该接” | ❌ 没这个字段 |
| **关系有止期，作废写止期而不删边** | “干净”和“留史”兼得 | ✅ 条目层有 `valid_to`（`openContracts`）；关系层没有 |
| **触发时机**（>10 min 回来 / 换话题 / 隔夜首句 / 对方不好受；每日≤ 2 条，同一根线 7 天不重复） | 每轮都查 = 把“查完就走”从一天一次变成一秒一次 | ❌ 只有“用户发消息 → 按查询召回”一种 |
| **沉降用机械事实**（没连着任何有效线 + 60 天没人碰），**不用重要性** | “别按重不重要砍，按还有没有线连着” | ⚠️ 有 `stage=dormant`，但判据是**权重分数** |
| **沉降前先问一遍**（留还是沉，7 天不响才沉） | 把“删”换成“沉”，但沉也得经它同意 | ❌ |
| **抽检 + 一句话拆线（`拆 L1`）+ 断开进黑名单** | “接错了没人管，错线只会越滚越多” | ❌ 没有任何“关系可管理”的入口 |
| **不打分** | “打分是给报表用的，不是给人用的”；“让我给自己排高低，排着排着就变成成绩单了” | ⚠️ 全系统靠 `weight`（见 11.3） |

### 11.2 它踩的坑，我们已经踩了一半

它列了四条踩坑，其中**两条在鲸鲸代码里正以"死代码"的形式躺着**：

| 它的坑 | 我们的对应物 |
|---|---|
| “假成功”：插件热重载日志说成功了，适配器根本没挂上 | `reconsolidate()` / `isFlashback()` 写好了**从没被调用**；`memory_links` **从没被读取** |
| “缓存盖回”：外部清理后，进程内旧缓存把文件整份写回 | 我们刚踩过同构的：`meta.embed_model` 只写不比对、DPAPI 解密结果没缓存（反向） |

它那句「加载成功 ≠ 生效，任何“装上了”的结论都要拿真实数据验一遍」，
和本项目 `HANDOFF §10` 第 3 条「**“写了”不等于“接上了”**」是同一句话。

### 11.3 一个必须说清的分歧：打不打分

它反对任何打分。我们整栋楼建在分数上——**但两者评的不是一件事**：

| 分数用在 | 它 | 鲸鲸 |
|---|---|---|
| 决定“值不值得记” | 反对 | 也基本没做（`importance` 只用于 `ORDER BY`，不参与衰减） |
| 决定“活多久” | 反对（连艾宾浩斯降权都否了） | **做**：拉伸指数 `w(t)` + 四段 `stage` + 双阈值滞后 |
| 决定“该不该冒出来” | 反对（用非分数判据：时间/换话题/情绪） | **在分数里**：FTS + cosine 排序 |

结论：**它把“浮现”从分数里拿出来了，我们没有。** 我们的分数只是比它讲道理（衰减数学而不是打分表）。
这一条不要含糊：我们“什么时候想起”仍是相似度决定的，不是时机决定的。

### 11.4 它比我们强在哪、弱在哪

| 维度 | 它 | 鲸鲸 |
|---|---|---|
| 浮现（原话 / 关系 / 时机 / 抽检） | ✅ 五版落地 | ❌ 基本是它的 v0 |
| 衰减数学（拉伸指数 / 四段 stage / 滞后带） | ❌ 明确拒绝 | ✅ 有公式、有测试、有参数表 |
| 契约层（永不衰减的边界） | ❌ | ✅ `layer=contract` + `openContracts()` |
| 隐私（shareable / local_only / taint 闸门） | 文章一字未提（不确定是没有还是没写） | ✅ 两处装配都有闸门 + 红队 |
| 可测（recall@5 / abstainF1 / 编造率 / 契约不腐） | ❌ “一天一天用出来” | ✅ 四个门 + 270 条测试 |
| 可回滚 / 可审计 | ❌ | ✅ 执行审计 + A/B 槽 |

**一句话：它做的是“浮现”，我们做的是“形状”。** 两件事不冲突，只是我们两边投入差了一个数量级。

### 11.6 它最后那句话，值得当判据用

> “接上去的线得让我看见，也得让我能拆。接错了没人管，错线只会越滚越多。”
> —— 记忆系统的第一原则不是记住多少，而是**她能不能管得住自己的记忆**。

这恰好对应 `docs/22` 的 **F 组（管理面）** 与 **D-1（可审计）**：我们缺的不是理念，是入口。
所以 J 组的四条全部带一个共同验收：**人能看见、能一句话撤销、撤销后不自动接回**。
