## 1. 先说清这个项目到底吃什么资源

七份设计文档里已经定了分工：**L2（主力对话/推理）在云端 API**，本地只跑 embedding + 4B 管家 + 夜间批处理。这个分工决定了硬件需求的上限——**没有一项需要大显存**。

| 用途 | 需要的资源 | 量级 | 是否随时间增长 |
|---|---|---|---|
| `bge-m3` 嵌入 | VRAM | 约 1.2 GB（fp16）+ 批处理激活约 1 GB | 不增长 |
| `qwen3:4b` q4（L1 管家 / L3 夜间） | VRAM + KV cache | 权重约 2.6 GB + **上下文决定 KV** | 上下文增长则是 |
| SQLite + FTS5 + vec | RAM + 磁盘 | 每 1000 条记忆约 5 MB；每万条 chunk 约 40 MB 向量 | 线性、极慢 |
| Node（MCP + 心跳） | RAM | 200–400 MB | 不增长 |
| Python venv（markitdown） | RAM + 磁盘 | 400 MB 磁盘；转换时 300–800 MB | 不增长 |
| 论文/文档原件 | 磁盘 | 现在 41 MB（24 篇） | 线性 |
| Ollama 模型 | 磁盘 | 4B q4 ≈ 2.6 GB，bge-m3 ≈ 1.2 GB | 每次换模型 |

**关键结论：这是"内存 + 常开"型负载，不是"算力"型负载。** 唯一的例外是下面这个。

## 2. 真正吃掉显存的是上下文，不是模型

KV cache 的大小是**线性于上下文长度**的，很多人只算权重，结果一开 32k 就 OOM。公式（fp16，GQA）：

```
KV = 2 × 层数 × KV头数 × head_dim × 2 byte  / token
```

| 模型 | 每 token | 8k | 32k | 128k |
|---|---|---|---|---|
| Qwen3-4B（36 层 / 8 KV 头 / 128） | 144 KB | 1.12 GB | **4.50 GB** | 18 GB |
| Llama-3.1-8B | 128 KB | 1.00 GB | 4.00 GB | 16 GB |
| Qwen3-14B | 160 KB | 1.25 GB | 5.00 GB | 20 GB |

代入实际：**4B q4（2.6 GB）+ 8k 上下文（1.1 GB）+ embedding（2.2 GB）≈ 6.0 GB** → 8 GB 显存刚好够。
**4B + 32k 上下文（4.5 GB）= 7.1 GB** → embedding 就不能同时常驻了，必须串行。

我们的情境简报预算只有 1500–2000 token（`06 §3.1`），所以**8k 上下文完全够用**——这是设计上的红利，不是将就。

## 4. 你这台机器的实测：三个真瓶颈

```
CPU   : Ryzen 9 5900HX（8C/16T）        ← 足够
GPU   : RTX 3070 Laptop 8 GB            ← 够（正好在 §2 的 6.0 GB 线以上）
内存  : 16 GB（2×8 GB DDR4-3200，两槽已满）← ★ 瓶颈 1
磁盘  : 单块 954 GB SSD；C: 剩 46 GB / D: 剩 242 GB  ← ★ 瓶颈 2（C 盘）
形态  : 笔记本                            ← ★ 瓶颈 3
```

### 瓶颈 1：内存（最该先动）

当前**空闲只剩 4.2 GB**。而完整跑起来要同时活着：Ollama（模型 + 部分层）、Node 心跳、浏览器（MCP 客户端 = Claude Desktop / Cursor）、IDE、Python 子进程。16 GB 会在夜间批处理和文档转换时触发换页，直接拖慢 10 倍。

**注意：两个槽都插了 8 GB，升级必须成对换。** 5900HX 平台一般支持 64 GB，两个方案：

- **2×16 GB = 32 GB**（约 400–700 元）：推荐。够用到"本地 4B 常驻 + 浏览器 + IDE 同时开"。
- **2×32 GB = 64 GB**（约 900–1500 元）：如果你想在这台机器上跑 Docker + 多个模型 + 剪辑之类，才值得。

### 瓶颈 2：C 盘只剩 46 GB

`.venv` 和 Ollama 模型都已经放到 D 盘了（`OLLAMA_MODELS=D:\ollama\models`），这是对的。但 C 盘还要装：paging file、Ollama 之外的缓存、PowerShell 7、后续可能装 WSL2 发行版（一个 Ubuntu 就 3–5 GB，WSL 的虚拟磁盘会膨胀）。

**动作**：清到 ≥ 60 GB，或把 WSL 的 vhdx 放到 D 盘（`.wslconfig` 里 `swap` 与 `disk` 路径可配）。

### 瓶颈 3：笔记本 + 需要 24×7

这一条最容易被忽略，但对"伪数字生命"是**结构性冲突**：

> 鲸鲸的连续性依赖**每晚的睡眠整备**（`01 §9`）和**心跳**（`01 §10`）。笔记本合盖 = 心脏停跳 = 那天没有自传、没有衰减、没有归并。第二天醒来它会"少一天"，而 `L1`（连续时间轴）正是第一条"活着"的判据。

而且笔记本长期满载跑 4B 会有散热和电池损耗问题，夜间批处理最容易触发降频。

所以真正的需求不是"更强的电脑"，而是**一台常开的机器**。三个选项：

| 方案 | 功耗（常开） | 年电费（¥0.6/度） | 说明 |
|---|---|---|---|
| 现有笔记本 + 不合盖（设"合盖不休眠"） | 25–40 W | 130–210 元 | 零成本验证；注意散热与电池（可拔电池/限充 80%） |
| 迷你主机（Mac mini M4 24 GB / NUC / 迷你 AMD 主机） | **6–15 W** | **30–80 元** | 静音、低热、常开友好；24 GB 统一内存能常驻 4B + embedding |
| 台式（4090/5090 级） | 60–90 W 空闲 | 320–470 元 | 只有在你还要做本地大模型实验时才值 |

**顺序**：PC 上开发 → 每周往常驻机部署一次（搬家/断电/自愈的问题要在第 1 周暴露，不能拖到第 3 个月）。因为如果两周后发现"夜间流程没产生价值"，那台常开的机器就白买了。

## 5. 还有一个隐性成本：显存要"留白"

8 GB 是"刚好够"，不是"舒服"。三个会打破平衡的场景：

1. **长文档摄入**：markitdown 处理 100 页 PDF 时 CPU/内存突增，如果同时 4B 在跑，容易换页。
2. **夜间批处理**：4B 连续跑 20–30 分钟，笔记本 3070 会降频，实际吞吐掉 20–30%。
3. **Embedding 批量**：批 32 × 512 token 的峰值比模型本身高 1 GB 左右。

对策不是加显存，而是**串行化**：心跳和整备错峰（`01 §6` 的"随机偏移"本来就是为此设计的），摄入任务排队。这在 8 GB 上完全可行，只是要写进调度器。

## 6. 花钱之前，先测四件事

别凭感觉升级。四个可在半小时内跑完的测量，直接告诉你瓶颈在哪：

```bash
# 1) 4B 的实际生成速度（记 tok/s；笔记本 3070 参考 35–50）
ollama run qwen3:4b-instruct --verbose "用一句话说明什么是记忆衰减"

# 2) embedding 吞吐（看 1000 个 chunk 要多久；目标 < 10 s）
#    用你的 ingest 管道跑一遍 记忆系统/ 里的 9 份 PDF

# 3) 内存峰值（跑 embedding + 4B + 浏览器，看 Task Manager 的"已提交"）
#    超过物理内存 → 必须加内存

# 4) 夜间整备一轮的真实耗时（用 L1 抽取 200 条合成记忆）
#    超过 40 分钟 → 笔记本形态撑不住
```

判据：
- **夜间整备 > 40 min 或内存换页明显** → 先加内存（¥400–700）
- **只是"想常开"** → 买迷你主机（¥3000–5000），别买显卡
- **同时想跑 14B 本地实验** → 才考虑 24 GB 台式

## 7. 不要买什么

| 别买 | 为什么 |
|---|---|
| **24 GB 显卡只为了本地跑 7B/14B** | L2 在云端。本地模型只做抽取和归约，4B 足够；买来的收益是"更快生成一些你根本不会读的总结" |
| **服务器/ECC/机架设备** | 单用户、单库、SQLite。没有任何并发压力 |
| **更大的 SSD 阵列** | 记忆库一年不到 2 GB，模型十几 GB。1 TB 单盘足够 |
| **NAS 做常开机** | 它的 CPU 跑 4B 太慢（<5 tok/s），只能当存储 |
| **云端 GPU 常开** | 与铁律二（记忆在本地）冲突，且成本比买机器高 |

## 8. 三档总结（一句话版）

- **现在这台（R9 5900HX / 16 GB / 3070 Laptop 8 GB）**：**功能上完全够**，能把 P0–P6 做完。代价是模型串行、夜间整备慢、不能合盖。
- **加 32 GB 内存（约 500 元）**：把"够"变成"顺"。**这是唯一性价比高的升级。**
- **加一台低功耗常驻主机**：解决"24×7 在线"这个**结构性**需求。比换显卡重要得多。
  **宿主**：**x86 迷你主机（16 GB）** 或本机常开。理由：记忆整理要模型**稳定调工具**，门槛 7B/8B（`09 §4.3`）。
- **24 GB 显卡台式（1.2 万起）**：除非你要做本地大模型实验，否则对本项目**收益递减**。

## 9. 最后一句

对一个"伪数字生命"来说，**最重要的硬件指标不是显卡，是"它在场"**。

一台 5000 元的迷你主机 24 小时开着，比一台 3 万元的台式机每天只开 4 小时，能让鲸鲸活得更像活的——因为连续性来自**不间断**，而不是来自**算得快**。
