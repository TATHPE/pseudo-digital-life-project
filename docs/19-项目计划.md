### W-A 为什么必须单列

`13 §2` 已经把角色配好了（`extract` / `salience` / `route` 全部 `kind: local`），但**计划表里只散落在三处**：0.4（embedding）、1.2（角色路由）、3.2（夜间抽取 1.5B）。这有三个后果：

1. 没有验收门 → 没人会真的验证"它没出网"
2. 冲突消解里那个 **LLM 判定分支**（`02 §8.2` 的模糊命中 >0.92）没指定模型 → 默认可能继承云端 → **记忆内容就出网了**
3. 本地模型不可用时没有定义降级 → 可能悄悄切云端

**所以 W-A 的硬规则**：凡是**能看到记忆原文**的模型调用，必须是 `kind: local`。代码里用一道断言守住：

```ts
// 所有进模型的请求都过这里
function assertLocalOnly(role: string, payload: string) {
  if (containsLocalOnlyMemory(payload) && roleKind(role) !== "local")
    throw new Error(`E_PRIVACY: role=${role} 试图把 local_only 记忆送出网`);
}
```

### 6.3 摄入管道（0.9）四处实现判断

1. **markitdown 走子进程，路径只进 `sys.argv`**。不拼命令串（T3 那一课的同一教训），`enable_plugins=False`，输出强制 UTF-8，出现 `U+FFFD` 直接拒收（`18 §5.1` 第 1 条）。
2. **`.md` / `.txt` 不走 markitdown**（passthrough）：本来就是纯文本，少一个失败点。
3. **「小于 80 token 就向后合并」有一个例外**：同一章节内的小尾巴、以及开头「不像句子」的小碎片（目录 / 标题串）才合；**内容具体但很短的章节保留** —— 它的 `heading_path` 本身就有检索价值。这一条是实测后加的（全合并会把 `# 衰减` `# 检索` 这类小节揉成一坨，章节名再也召不回来）。
4. **块级去重会真的删掉重复段落**（同文档内 sha256 相同 → 保留首个）。写测试时注意：拿「同一句话重复 40 遍」当样例，会只剩两块，这是正确行为。

**已知限制**：部分 PDF 经 markitdown 会**丢词间空格**（`Largelanguagemodelagents…`），英文召回变差，中文不受影响。真源与规范化 markdown 都在库里（`data/markdown/`），换转换器时可整库重建。

### 6.4 文档块怎么进 P10（0.10）

接进 P10 时有一个**必须先解决**的问题：P10 会跟着简报发给 express 角色，而 express 常常是云端的。
所以不是“把召回拼上去”就完了，是把**闸门建在装配处**：

| 来源 | 默认 | 进 P10 的条件 |
|---|---|---|
| 记忆 | 聊天里说的 = `shareable`，磁盘摄入 = `local_only` | 只放 `shareable` |
| 文档块 | **全部 `local_only`**（`documents.sensitivity` 默认值） | 面板里点“标为可发送”，或 `ingest --shareable` |

没进 P10 的东西**不隐瞒**：简报里会写“另有 N 条本地记忆、M 段本地文档未发送”（`recall.ts` 的 `omissionNote`）。
它知道“我还记得别的，只是这里不能说”，而不是假装那些东西不存在（`07 §3` 的诚实条款）。

装配这一步单独拎成 `src/recall.ts` 也是为了能**直接单测**：`test/recall.test.ts` 里断言“local_only 的文档块一条都不会出现在 `recalled` 里”。
这一条比读代码更可靠——隐私闸门不能靠“大家都记得要过滤”。



### 6.1 5.5 的两处有意偏离（写给下一个人）

1. **事实源是 `deploy/state.json`，不是 `current` 软链。** Windows 建目录软链要管理员/开发者模式，junction 又不能跨卷；一条悬空的 `current` 会让“启动即挂”。软链仍然建（尽力而为），但只给 systemd 与人看，判断一律读能原子写的 `state.json`。
2. **“人格回归 10 问”实现为 10 项人格不变量**（齐全 / 非空 / 无控制字符 / 无 U+FFFD / 无密钥 / 无主机绝对路径 / 无软链 / 预算）。真去问 10 个问题要花 API 费、答案不确定、离线跑不了 —— 放进发布闸会让“发布”变成“有时通过”。真问题留给 `jingjing eval --model`。

冒烟 20 项分组与 `18 §4.3` 一致：① 能启动 / 库可读 / 三重指纹（1–10），② 人格（11–20）。

### 6.2 5.6 的三处判断（写给下一个人）

1. **档位跟着模板走，不是整个 verb 恒 T3。** `git.status` 是 T1（只读，不该每次问），`node.run_script` 是 T3。实现是 `VerbDef.tierFor(args)`：策略看到的 tier 就是模板的 tier，于是"只读”与“能执行代码”在 `policy.csv` 里是两行，可分别开关。
2. **确认的载体是令牌，不是 `--yes` 布尔。** `--yes` 只是“人就在跟前”的标记：现场签发一枚绑定到这条 argv 的令牌、立即用掉。模型永远拿不到令牌，因此“确认一次后连续十轮”在设计上不成立。
3. **Windows 双栈（PS 5.1 / 7）在本实现里不适用。** 我们不生成任何 shell 字符串，一律 `spawn(argv)` 直调 —— `&&` / `??` / 引号那三个坑直接不存在（`04 §5.3` 的取舍）。代价：只能用二进制本身的能力，没有管道/重定向（要管道就再注册一个模板）。

**沙箱是可选增强，默认不开**：`JJ_SHELL_SANDBOX=docker` 时走 `--network=none --read-only --cap-drop=ALL`，只把 `workspace/` 挂进去；引擎不在就拒跑（`E_SANDBOX_UNAVAILABLE`），只有 `JJ_SHELL_ALLOW_DIRECT=1` 才能显式降级，且审计里记 `direct(...)(降级)`。

**仍然没做的**：Job Object / bwrap / 降权 / 低完整性级别（Windows 上要原生模块）。默认（非容器）模式下，隔离靠的是：模板白名单 + 正则槽 + 进程树超时 + 环境白名单。

### 6.5 面板可用性（0.11）：从"调试面板"到"能用的产品"

之前的面板是给作者看的：信息全、但没有证据、没有闭环、没有容错。这一批补齐 23 项，分三层：

| 层 | 补了什么 | 为什么重要 |
|---|---|---|
| **证据** | 召回行（这一轮用了哪几条记忆/文档，含"另有 N 条仅本地"）、正文里的 `mem:` / `doc:` 变成可点引用、动作审计视图（`exec_audit`）、版本/冻结 chip | 这个产品的卖点是"它记得"。**不可验证的记得 = 自说自话** |
| **闭环** | 面板内摄入文档、停止生成（前后端一起停）、搜索（记忆 + 文档）、记忆纠错（改正文/重要性/敏感度）、测试连接、今日花费 | 用户不该为了加一篇文档去开终端；"停止"如果只停了 UI，token 照烧就是在骗人 |

1. `hidden` 属性能被类里的 `display` 压掉 → 待确认角标**永远显示**。全局加 `[hidden] { display:none !important }`。
2. `<textarea>` 不写 `height` 会自己撑成一大块，把时间轴挤掉一半。
3. 把单行 `input` 换成 `textarea` 时，原来的 `form#composer input { flex:1 }` 选择器**没覆盖到它**。

一个印证：问"记忆动力学里衰减和再巩固怎么说的"时，因为那篇文档是 `local_only`，它**没有**从简报里拿到内容，而是自己去调了 `doc.search`（56 ms）把章节捞回来——隐私闸门和工具面同时在工作，界面上两头都看得见。

1. **写操作守卫要认“同源”**。原来只认回环 Origin —— 手机通过 Tailscale 打开时 Origin 是 `https://xxx.ts.net`，于是**能看不能动**（发消息、改设置全 403）。改成“回环 **或** Origin 的 host == Host 头”；跨站仍然拒，`x-jj` 头仍然要（跨站发不出自定义头，预检不放行）。
2. **图标是构建期真渲染出来的 PNG**，不是运行时画：headless Edge 把面板里同一个鲸尾 symbol 渲染到 512/192/180 三个尺寸（`tools/icons` 一次性脚本 → `src/web/static/`）。manifest 里的每个图标都有测试断言“真能取到、真是 PNG”。
3. **手机上抽屉原本没有开关**。`aside` 在 ≤860px 是 `translateX(-102%)`，但没有按钮能把它叫出来 —— SESSIONS/DOCS/MEMORY/TOOLS/CONFIG 全部不可达。现在 header 左侧有 `≡`，抽屉改实底 + `box-shadow` 遮罩（伪元素 `z-index:-1` 会被 aside 自己的背景盖住，等于没有）。
| 6.6 ❌ | ~~Pi 接入~~ → **改成「常驻主机选型」** | — | **2026-10-28 取消**：本地模型必须能稳定调工具，门槛是 7B/8B；Pi 上跑不动（见 `09 §4.3`）。替代任务：x86 迷你主机（16 GB）或本机常开 + Ollama 7B |

**6.1/6.2/6.3 的三处实现细节（都是实测前想不到的）**

1. **容器内必须绑 `0.0.0.0`**（`JJ_BIND`），否则宿主的端口映射打不进来——容器的 `127.0.0.1` 不是宿主的 `127.0.0.1`。
   但 compose 只把 `0.0.0.0:7700` 映射到 **宿主回环** `127.0.0.1:7700`，两步合起来才既可达又不裸露。
2. **`docker kill` 不触发重启策略**（它等价于手动停止）。要让 `restart: unless-stopped` 真生效，得让进程自己退出；测法是 `RestartCount` 而不是“看它还活不活着”。
3. **`--test` 不能当启动命令**：断电检测/补算衰减在 `serve` 的 `startup()` 里，容器换了入口就全丢了。

在 PC 上把数据卷/重启自愈/健康检查这些跑顺，搬到迷你主机时只剩"换机器"这一个变量（同一架构，连镜像都不用重编）。
