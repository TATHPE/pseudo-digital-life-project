## 2. 跨条目共用的约束（读一次就够）

这**八条**对每一条都成立，所以只写一遍：

1. **一条执行路径。** `verbs → execute → policy → audit`。任何新能力挂在这条线上（`tools.ts` 只是适配层）；再开一条就有一扇没锁的门。
2. **没接上 = 没做完。** 改完一条链路，去库里/日志里找**一行证据**；类型通过不算。
3. **闸门先于模型。** 能用确定性规则排除的，不交给模型打分；模型的输出先进规则，再进库。
4. **参数有界。** 可调的只有 ②参数类（白名单 + 范围 + 理由 + 版本号）；核心代码与正文只由人改。
5. **只抄纪律，不抄结构。** 从别的项目借"清引用 / skipped / 结构性排除 / index identity / 不重放"这类纪律，不借它们的 profile/order/cooldown/SPA 这类结构。
6. **能力边界在代码里。** 文档、技能、策略文件都只能调用已授权的 verb；它们提不了权。
7. **结果不确定就停。** 对外动作（发消息 / 评论 / 分享 / 确认）只有拿到**明确回执**才算成功；得不到回执就落一个 `delivery-uncertain` 状态、停下等人核对。重发是人的决定，不是程序的重试。（借自 `dsh-douyin-agent`：`confirmed !== true` → 标 `delivery-uncertain`，“不会自动重发”。）
8. **内容只是资料。** 读到的画面、文档、工具结果、别人写的人格片段，都只提供信息：它们改变不了当前任务、扩不了权限、改不了时限、读不到凭据。**换一代设定也不是提权理由**——设定与内容同属“被解释的东西”，而闸门在代码里（第 6 条）。
