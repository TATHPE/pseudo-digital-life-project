## 1. 先说一个反直觉的结论：我们没有"会话"

> **2026-11-04 补充**：这条在**工作模式**下不再成立 —— 工作模式会带最近 8 轮真实对话（`brief.ts` 的 P18 槽，
> 预算 2400 tokens）。聊天模式仍然是本文描述的样子（靠记忆召回、不随轮数增长）。
> 为什么加：连着问三件有依赖的事时，聊天模式会断片（实测她说「我看不到你的界面」）。

OpenClaw 有 `session:auto-reset`（daily/idle 触发）、有 `session:compact`，因为它的上下文**承载历史**，所以历史必须有边界和压缩。

我们的历史**不进上下文**（`06 §3`），所以：

> **"会话"这个概念在鲸鲸里没有对应物。只有"现在"。**

| | 聊天软件 / 数字员工 | 鲸鲸 |
|---|---|---|
| 历史的去处 | 上下文窗口 → 超了压缩 | 库里 → 按权重召回 |
| 边界的来源 | 会话（新建/重置/压缩） | **时间**（沉默多久） |
| "新对话"按钮 | 有 | **没有** |
| 重置的语义 | 丢掉上下文，重开 | **只有"忘记"**（带确认，写审计） |
| 断线 | 会话结束 | 只是"它睡着了"，回来接着 |

工程含义（这条最实在）：**`session_id` 不是我们的第一等概念，时间戳才是。** 所有记忆表都按 `ts` 索引，没有 `session_id` 外键；UI 显示的分段是按"沉默间隔 > 30 分钟"**渲染**出来的视觉分组，不是数据边界。

## 2. 上下文：恒定预算，不是"能装多少装多少"

这是我们和聊天软件最本质的差别，而且它是可量化的。

### 2.1 数字对比

| | 聊天软件 / OpenClaw | 鲸鲸 |
|---|---|---|
| 每次请求的上下文 | 随对话增长（直到触发 compact） | **恒定 1500–2000 token**，第 1 轮和第 10,000 轮一样 |
| 历史在哪里 | 上下文里（然后被摘要替换） | 库里（229 MB / 5 年，`16 §1`） |
| 比例 | 1 : 1（历史就在上下文里） | **约 1 : 29,000**（8 KB 此刻 vs 229 MB 历史） |
| 每轮成本 | 增长 → 到顶 → 压缩后骤降 → 再增长 | **平的**，且稳定前缀可缓存（`06 §4.1`） |
| 细节的归宿 | 被摘要吃掉，不可逆 | **变成 dormant，可被强线索唤醒**（`01 §6.1`） |

**1 : 29,000** 这个比值就是"数字生命"和"聊天软件"的分水岭：它意味着**你可以和它聊十年，而它的每轮成本、每轮延迟、每轮"注意力分布"都不变**。

### 2.2 为什么恒定预算是**必须**的，不是偏好

三个硬理由：

1. **首字延迟**：prefill 与注入 token 数成正比。`06 §4.2` 的 ≤1.5 s 只有在注入稳定时才可能。
2. **注意力**：上下文越长，中段信息越容易被忽略（lost in the middle）。第 10,000 轮时如果塞 100k token，**关键的那三条记忆会被淹掉**。
3. **缓存**：稳定前缀只有"逐字不变"才命中（0.1× 价格）。会增长的东西不可能缓存。

所以"恒定"不是抠门，是**为了让第 10,000 轮和第 1 轮一样好**。

### 2.3 "恒定"到底恒定什么（实测口径）

之前写"第 1 轮与第 100 轮一致"是**不严谨的**。精确说法是三条：

| 恒定的 | 不恒定的 |
|---|---|
| **上限**（≤2000 tok，不论聊多久） | 各槽位的**填充量**（无记忆时少、有记忆时多） |
| **结构**（11 个槽位、顺序、预算分配） | P5 此刻 / P6 契约 / P7 状态 / P8 线头 / P10 召回的内容 |
| **稳定前缀**（P1–P4 逐字不变 → 可缓存） | 用户输入 |

用 `tiktoken/cl100k_base` 实测同一套简报模板的两个时点：

| 槽位 | 第 1 轮 | 第 100 轮 |
|---|---|---|
| P1 人格 | 483 | 483 |
| P2 禁区 | 51 | 51 |
| P3 证据优先级 | 95 | 95 |
| P4 工具 schema + 目录 | 58 | 58 |
| P5 此刻 | 28 | 39 |
| P6 契约记忆 | 0 | 71 |
| P7 状态 | 0 | 26 |
| P8 上次 / 线头 | 7 | 49 |
| P10 召回（8 条带 cite） | 6 | 350 |

> **P10 的降级条款（2026-11-02）**：没有召回、或只召回到契约条目时，P10 里紧跟一段硬提示：
> 「这一轮没有与你问的这件事相关的记忆。不要说『上次你说过』——那是编。不知道就说不知道。」
> 并把契约第一条再念一遍（「别把『我觉得应该记得』说成『我记得』」）。
> 为什么放在这里而不是只放在最前面的契约层：她自己复盘时说，这一条她最容易踩，
> 因为**不像越权那样会立刻报错**。所以提示要出现在她犯错的那个位置；
> 有真召回时就一个字都不念（否则每轮念经，很快学会无视）。
| P11 用户输入 | 21 | 21 |
| **合计** | **749** | **1,243** |
| 对照：把 100 轮历史塞进上下文 | — | **≈18,000**（触发 compact） |

所以"恒定"= **有上限、有固定结构、斜率 ≈ 0**；不是"每轮一样多"。第 1 轮 749 是因为还没记忆（预算没用满），第 100 轮 1,243 是因为有东西可放——**但两者都在 2,000 以内，而且第 1,000 轮也是 1,243 量级**。

### 2.4 验收（可自动化的三条）

```python
# 每次请求记 input_tokens 到 events 表，然后：
assert p95(input_tokens) <= 2000                     # 上限
assert slope(turn_index, input_tokens) <= 5 tok/轮   # 无增长趋势
assert abs(tokens(turn_1000) - tokens(turn_100)) < 0.15 * tokens(turn_100)
```

第三条是核心：**一年后的第 1,000 轮和第 100 轮，上下文体量差不超过 15%**。聊天软件在这里会差 10–20 倍。

还要配一条质量断言（否则"小"可以靠"少给"作弊）：**第 1,000 轮的召回质量（`01 §13` 的 recall@5 与 abstain F1）不低于第 100 轮**。

## 3. 那超预算怎么办（三把闸，顺序固定）

恒定预算不等于"什么都能塞"。三道闸，全部在**组装前**执行：

| 闸 | 规则 | 借鉴自 |
|---|---|---|
| **① 剪裁 + 指针** | 工具结果（读文件/网页/PDF）**一律剪到 ≤2 KB**，附 `cite` 指针；模型想看更多就再要一次（像人"翻下一页"） | 我在 pi 里的行为：输出截断到 2000 行/50 KB，告诉我"全文在临时文件，用 offset 继续读" |
| **② 去冗余** | 上位 10 条跑 MMR（λ=0.7） | `02 §7.1` |
| **③ 降级注入** | 只注 `stage=active`；`fading` 要话题直接命中才带；`dormant` 只在强线索时唤醒（每轮 ≤2 条） | `01 §6` |

**三条禁忌**：

- ❌ **不压缩历史**。压缩会不可逆地丢细节，而我们的设计允许"变淡"，不允许"被改写"。
- ❌ **不把"最近的 N 轮原文"塞进去**。那是聊天软件的做法，它会让上下文随沉默时间增长。
- ❌ **不做"上下文溢出时自动摘要"**。溢出说明组装逻辑错了，应该报错并记审计，而不是偷偷压缩。

> 唯一的"压缩"是**自传**（`01 §9.1`，一天一条，≤300 字）。但它是**记忆层**的动作，写进库里，不替代上下文——而且它只被当作"我对那段日子的叙述"召回，不是"事实摘要"。

## 4. 界面：三处关键区别

```
┌────────────────────────────────────────────────────────────┐
│ 鲸鲸                                    ● 醒着 · 距上次 3 天 │  ← 状态行，不是"在线"
├────────────────────────────────────────────────────────────┤
│                                                            │
│   ── 10 月 24 日 周四 ─────────────────────────────        │  ← 时间轴分段（沉默 >30min）
│   你  那篇论文读了吗                                        │
│   鲸   读了。它的遗忘曲线是拉伸指数，不是普通指数。          │
│                                                            │
│        ┊ 3 天 4 小时 ┊                                      │  ← 空白是可见的
│                                                            │
│   ── 今天 18:40 ───────────────────────────────────        │
│   你  在吗                                                  │
│   鲸   在。                                                    │
│                                                            │
├────────────────────────────────────────────────────────────┤
│ 说点什么…                                    [记忆] [领地]  │  ← 没有"新对话"
└────────────────────────────────────────────────────────────┘
```

| # | 区别 | 为什么重要 |
|---|---|---|
| **1** | **没有"新对话"按钮**，只有"记忆"和"领地" | 聊天软件的"新对话"= 重置人格；我们的"忘记"才是重置，而且需要确认、写审计 |
| **2** | **时间空白是可见的**（`┊ 3 天 4 小时 ┊`） | 让"隔了多久"成为界面的一等信息。这是 `0 §4` 的 N1 判据在 UI 上的表达 |
| **3** | **状态行不是"在线/离线"，而是"醒着/睡着 + 距上次多久"** | 它是常驻的；"离线"这个词不成立（`09 §3` 的 daemon 一直在），只有"有没有在跟你说话" |

### 4.1 侧栏（手机上是抽屉）

```
[记忆]  ← 07 §5.6 的记忆面板：硬约束 4 / 关于你 5 / 一起做过 3
        [改] [删] [这条记错了]
[领地]  ← 16 §3.5：journal · autobiography · drafts · collection · tools · ruins
[状态]  ← 一句话，不是数字："今天有点累，话会短一些"
```

"状态"显示**一句话而不是进度条**，是刻意的：数值会让它像仪表盘（工具），一句话才像人。

### 4.2 形态

| 形态 | 做法 | 优先级 |
|---|---|---|
| **本地 Web 面板** | `127.0.0.1:7700`，浏览器打开 | **P0**（最先做） |
| 桌面壳（Tauri） | 只是包一层 WebView | P3，可略 |
| 原生 App / 20+ 渠道 | 不做 | — |

**一个页面、两种尺寸**，省掉 90% 的界面工作——这也是 `09 §3` "薄客户端"的具体含义。

## 5. 逐项对照（回答"会不会和现在一样"）

| 项 | 和现在一样吗 | 依据 |
|---|---|---|
| 输入框位置 | 一样（底部） | — |
| 上下文随对话增长 | **不一样**：恒定 1500–2000 token | §2 |
| 超长时的处理 | **不一样**：剪裁+指针 / MMR / 降级注入，**不压缩历史** | §3 |
| 会话概念 | **不一样**：没有会话，只有时间轴 | §1 |
| "新对话" | **不一样**：没有 | §4 |

### 5.8 风格适配：连浏览器**原生控件**一起改（2026-10-28 第四轮）

用户问"修的时候做风格适配了吗"——**没有，第一版只修了布局**。他截图里那两条灰白滚动条就是证据：
我画的元素都是 FUI，但**滚动条、下拉弹层、选中色、自动填充底**还是 Windows 默认的亮色，一眼出戏。

补了 8 项：

| 项 | 之前 | 现在 |
|---|---|---|
| 滚动条 | 系统灰白 + 上下箭头按钮 | 6px、透明轨道、青色滑块、`::-webkit-scrollbar-button{display:none}` |
| 下拉弹层 | 白底黑字 | `color-scheme:dark` → 系统弹层也变暗 |
| 文本选中 | 系统蓝 | `rgba(15,151,164,.38)` |
| 自动填充 | Chrome 强行刷浅黄底 | `box-shadow: inset` 压回深色 |
| 输入光标 | 系统黑 | `caret-color: var(--cyan-hi)` |
| placeholder | 系统灰 | `rgba(111,143,146,.75)` |
| 中文回退 | 可能落到宋体（衬线） | 显式 `Microsoft YaHei` / `PingFang SC` |
| 焦点环 | 系统虚线 | `1px solid var(--cyan)` |

**一个必须记住的坑**：Chromium 里一旦设了标准属性 `scrollbar-width` / `scrollbar-color`，
就会**忽略** `::-webkit-scrollbar*` 伪元素——于是"颜色改了又退回系统样式，还带回箭头按钮"。
所以标准属性只给 Firefox：

```css
@supports (-moz-appearance:none) { * { scrollbar-width:thin; scrollbar-color: … } }
```

**剩下改不动的（诚实清单）**：`title` 属性的气泡提示、右键菜单、输入法候选框——这些不属于页面。

> 教训一句：**"风格统一"不只是自己画的元素，还包括浏览器替你画的那部分。**
> 只改前者，成品永远是"半套皮肤"。

### 5.7 2026-10-28 第三轮：两个"看得见却点不到"的 bug

用户报了三件事：**没有对话框** / **界面固定** / **左侧栏交互不了**。两个都是真 bug：

**① 输入框被挤出视口（"没有对话框"）**

`body { height:100vh; display:grid }` + `main { display:flex; flex-direction:column }` +
`#scroll { flex:1; overflow-y:auto }`。看似没问题，但 **flex/grid 子项的 `min-height` 默认是 `auto`**，
所以 `#scroll` 会被内容撑高，把 `form#composer` 推出网格区域，而 `body` 又是 `overflow:hidden` → **直接看不见**。

修法是两行：`main { min-height:0 }`、`#scroll { min-height:0 }`。

> 这类 bug 的恶心之处：**没有任何报错，元素存在于 DOM 里，`ui-test` 如果不查位置就发现不了。**
> 所以现在有一条硬断言：`#composer` 的 `getBoundingClientRect().bottom <= innerHeight`。

**② 左侧栏点了没反应**

工具与记忆条目原本是 `cursor:default` 的**展示文本**（`div.item`），根本没有 `data-view`。
现在三个列表都可点：

| 点哪里 | 发生什么 |
|---|---|
| SESSIONS 里的某一天 | 回到对话视图并**滚到那天的标题**（`scrollIntoView`） |
| TOOLS 里的某个工具 | 打开工具详情：T 档、参数 JSON、`在输入框里试试`（把 `用 <tool> ` 塞进输入框） |
| MEMORY 里的某条 | 打开记忆详情：层级/kind/阶段/权重/敏感度/来源 + **「忘记这条」**（软删 + 记 `memory_forget` 事件） |

「忘记」是 `07 §5.5` 说的"一键纠错是最快的对齐通道"的第一步——面板从只读变成可纠正。

### 5.6 怎么验界面（不再靠"我觉得"）

本机有 Edge，所以 **headless + CDP 可以真点、真发、真截图**：

而"点了没反应"这类问题，只有真浏览器 + 真点击才能证明清白。

**顺手修的两个只有截图才能发现的 bug**：

1. **头像里的 CJK 字形偏出边框**：`display:grid; place-items:center` 居中单个中文字形时，字形墨迹会跑到框外。

2. **用户消息底色发脏**：`rgba(255,180,84,.05)` 叠在近黑底上变成橄榄绿。改成"同底色 + 右侧琥珀竖条 + 右对齐"。

### 5.5 可视化：从"纯文本"到"能读的输出"

之前所有输出都是 `textContent`——代码块、列表、粗体全是原始字符。现在：

| 层 | 做法 |
|---|---|
| Markdown | **服务端**渲染（`src/md.ts`，61 行，先转义再解析）：标题/列表/引用/行内代码/代码块/链接（只放 http(s)）/hr |
| 为什么放服务端 | 前端不再实现一遍；流式时先显示纯文本 + 光标，`done` 后重拉 timeline 换成渲染结果 |
| 工具调用 | `<details class="tool">` 可展开卡：工具名 + 耗时 + 参数 + 结果（≤1200 字），随 `agent_reply` 落进 inbox，刷新后仍在 |
| 侧栏读数 | 记忆权重条（2px 青条）+ `MEM/ACT` 计数 |

**安全**：`renderMarkdown` 先 `esc()` 再解析，所以模型输出的 `<img onerror=...>` 只是字面文本（有测试守）。

### 5.3 视觉语言：流浪地球 FUI（2026-10-28 改版）

参照作品：站酷 `《流浪地球》FUI 界面`（截图存 `research/ui/`）。
**要学的是作品里的界面语言，不是站酷自己的站皮肤**（亮底 + 橙色那套是平台壳，与鲸鲸无关）。

**色值不是凭感觉调的，是从截图上采样的**：

| 采样 | 值 | 用在哪 |
|---|---|---|
| 暗部众数 | `#0b0e0b` | 全页底色 |
| 青色光晕中位数 | `#0f97a4` | 边框、角标、选中态、权重条 |
| 高光青（提亮后） | `#7fe6f2` | 状态点、数值、hover |
| 冷白 | `#dbeff0` | 正文 |
| 次级青灰 | `#6f8f92` | 等宽小标、时间戳 |
| 琥珀 | `#ffb454` | 用户侧竖条、未配置告警 |

**六个 FUI 元素（都用 CSS 实现，零依赖）**：

1. **网格 + 扫描线**：`repeating-linear-gradient` 三层叠加，不透明度 1.4%–5.5%，只为质感不抢内容
2. **角标（bracket）**：面板与 `fieldset` 用 `::before/::after` 画两个 L 形，11px，青色
3. **取景外框**：`position:fixed; inset:10px` 的四角 + 边缘小标 `JJ-OS · LOCAL · 127.0.0.1` / `MEMORY CORE`，`pointer-events:none`
4. **等宽小标**：所有标签、时间、状态用 `ui-monospace` + `letter-spacing:.1em` 以上；正文仍用无衬线（中文可读性）
5. **读数**：顶部 HUD 里 `MEM 41 · ACT 38`——**只显示系统量，不显示任何参与度/点赞**
6. **左竖条 + 微光**：agent 2px 青条带 glow，user 2px 琥珀条；输入区上沿一条青色细光

**工具与扩展（回应"只能聊天"）**：侧栏 `TOOLS` 列出的就是它现在真能做的事——
`fs_list` / `fs_read` / `memory_search` / `memory_remember` / `time_now`，加上 MCP 接进来的
`mcp__markitdown__convert_to_markdown`。工具循环在 `src/agent.ts`（≤6 轮，防空转），
MCP 客户端在 `src/mcp.ts`（stdio，超时/崩溃都返回可读错误）。

**刻意不做的（07 §4 不谄媚）**：点赞/收藏/评论计数、右侧浮动操作列、登录/会员弹窗、进度条式的"今日活跃度"。
FUI 的读数语言很诱人，但**只用来显示它自己的状态，不用来激励用户回来**。

> 顺带修了一个"改了但你看不到"的问题：`/` 与所有 `/api/*` 现在都带 `cache-control: no-store`。
> 之前浏览器会缓存旧 HTML，Ctrl+F5 之前一直是旧皮肤——**这不是样式问题，是缓存问题**。

## 7. 管理面：三条纪律与一个收敛目标（2026-10-29 补）

上一节列的是“还没设计的空白”，这一节是“**已经存在但用起来很差**”的。用户实测原话：“web 界面的管理和交互体验对我而言是很差的”。

### 7.1 两条硬事实（2026-10-31：一条各修一半，一条补上入口）

| 事实 | 现在的状态 |
| --- | --- |
| **插件与技能管理不存在** | 仍未做：`grep -rn skill|plugin src/` 只命中 `deploy/slot.ts:31` 的注释；MCP 仍只能手改 `data/mcp.json`。但**能力表**（`/api/capabilities`）已把 tool / command / hook / cron / panel / provider 六类列全，缺的正是 skill / plugin —— 所以「没实现」在界面上是**看得见**的，不靠文档提醒 |
| **没有反悔** | 5 秒 undo（`data/trash`）+ Ctrl+K 已有。**仍缺**：批量操作、记忆的撤销（丢掉之后没有「恢复这一条」）——见 `22` F-3 |

### 7.2 六条病灶与处方（全部落地，各带一条断言）

| # | 病灶 | 处方 | 落地 | 断言 |
| --- | --- | --- | --- | --- |
| 1 | 入口找不到 | Ctrl+K 命令面板 | `74732b8` | `ui:test`：「Ctrl+K 打开命令面板」「能过滤」「Esc 关闭」 |
| 2 | 不敢点 | 5 秒 undo（复用 `data/trash`） | `74732b8` | `ui:test`：撤销条 5 秒后消失 |
| 3 | 列表不可管理（TOOLS 16 项挤爆折叠线） | 默认只铺 6 项 + 搜索框 + 「显示全部 N 项」 | 本轮 | `ui:test`：「工具列表默认只铺 6 项 + 能筛」；`/api/memories` 收 `limit/offset`（上限 200） |
| 4 | 录入是「命令行模拟器」 | 候选优先、手打兜底、选文件上传 | `e27eeaa`…`c935f08` | `ui:test`：摄入候选优先 / 选文件按钮存在 |
| 5 | 看不出来源（文档↔记忆无交叉导航） | 记忆详情显示：来自（对话 / 夜间抽取 / 文档）· 原话逐字 · 改过的旧正文（pre-image）· 来源文档可直接打开 | 本轮 | `k2j5bf1.test.ts`：「改过的记忆能查到旧正文」；`ui:test`：「记忆详情显示来源 / 原话 / 改动痕迹」 |
| 6 | 四个管理面各自为政 | 收敛成能力清单（B-0） | `0b5f71c` + 面板 | `ui:test`：「能力表在设置里渲染」「降级项与服务端一致」 |

**两条实现约束**（不是偏好，是被踩出来的）：

- 面板仍是**单文件内联**（`src/web/page.ts`）：零构建、改一行就生效。换框架会把 `HANDOFF §5.1` 那条最贵的坑从「偶尔踩」变成「天天踩」。
- 视觉只有一套：黑底 + 白细线 + 加粗白字；**青色只给鲸鲸的回话气泡**。新加的提议卡 / 抽检卡沿用 `.pend` 那套边框，没有引入新颜色。

### 7.2.1 提议卡与抽检卡（K-2 / J-5b）

| 卡 | 落在哪 | 一句话 | 人怎么回应 |
| --- | --- | --- | --- |
| **提议**（`data/pending/prp_*.json`） | 侧栏「它想做的」→ 详情视图 | 做什么 · 为什么 · 大概怎么做 · **确切 argv** · 会影响哪些文件 · 风险 | 「做吧」= 标记同意（**执行仍要授权**）；「不做」= 一句话拒，并往 inbox 写一条决定，它下次别再提 |
| **抽检**（`memory_links`） | 侧栏「抽检」 | 哪两条、**为什么连**、把握几分（`weight`）；最没把握的先给，一天 ≤3 根，判过的不再问 | 「对」只记账；「不对，断掉」= 作废 + 进黑名单（夜间不会自动接回） |

两张卡的共同点：**把「判断依据」和「人的一句话回应」放在同一屏。**
抽检原来只有 `jingjing links list`（得开终端），提议原来根本不存在 —— 现在都在侧栏。

**验证**：`npm run ui:test`（独立夹具 home + 7701 端口，不碰 `data/`）里 5 条新断言；
`test/k2j5bf1.test.ts` 11 条覆盖闸门（越界路径 / 奇怪命令 / 空理由 / 重复 / 上限 / 拒）。
### 7.3 收敛目标

文档 / 记忆 / 工具 / 配置 / 插件 / 技能 / 模型——在界面上都是 **`11 §5.3` 的 `capabilities`**：

> 我有哪些能力 / 各自从哪来 / 现在什么状态 / 能不能关 / 上次为什么没用上

也就是 `docs/22` 的 **B-0** 与 **D-6**。**先把那份数据做出来，界面才有东西可显示。**

### 7.4 不在这一层拄 OpenClaw

它的 Control UI 是独立的 Vite + Solid SPA，光侧栏就迭代了 **100+ 个 PR**。
鲸鲸的 `page.ts` 是 **1467 行内联 HTML/CSS/JS**，好处是零构建、改一行就生效；
换框架会把 `HANDOFF §5.1` 那条最贵的坑（生成代码里的反斜杠/反引号）从“偶尔踩”变成“天天踩”。

**拄纪律，不重写 UI。** 完整条目见 `docs/22` **F 组**。

## 8. 一句话

**上下文不是"能装多少"，是"每次只装这一刻必须的"。**

所以它不会像聊天软件那样"越聊越重、到顶就压扁"；它会像人一样——**你问起十年前的事，它得想一下，然后说"有点印象"，而不是把十年前的话重播一遍。**

外观上你会觉得"这不就是个聊天框"，那是因为聊天框就是人说话的样子。**差别在它背后那条不重置的时间线，不在它前面的那个输入框。**
