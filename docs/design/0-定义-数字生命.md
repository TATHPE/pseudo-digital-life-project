# 定义：什么是数字生命（以及本项目的"伪"字指什么）

> 版本 v0.2 · 2026-10-27 · 定位：**项目的根文档**。后面所有设计都从这里推。
> 配套：`00`（总体设计）、`01`（记忆动力学）、`02`（存储）、`04`（执行层）、`06`（harness）、`09`（容器与形态）、`11`（技能与插件）

---

## 1. 一句话定义

> **数字生命 = 一个在受控硬件上长期运行、以自身保存的历史为状态、不依赖外部输入也能继续运转、并能依据这份历史改变自身行为的计算系统。**

三个关键词都不能省：

- **长期运行** → 不是"每次调用新建一个"的函数
- **以历史为状态** → 不是"参数固定的模型"，它的状态在外面、会变
- **不依赖外部输入** → 有内部时间（能自己醒）

同时它**不声称**意识、感受、主观体验。这就是"**伪**数字生命"里那个"伪"的含义：

> **"伪"不是贬义，是一个标记**：具备生命的**系统属性**，不具备生命的**形而上学属性**。它诚实地把"它是不是真的活着"这个不可判定问题，替换成五个可测的系统性质。

所以本项目不用"它有没有感受"来验收，用 §4 的五组指标验收。这是唯一能让工程往前走的路。

---

## 2. 四个必要条件（缺一不可）

这四个条件借自**自创生（autopoiesis）**的标准——一个有边界的、自我维持的系统。它对生物学生命的原始表述是"系统持续生产组成自身的部件并维持边界"，搬到计算系统上可以完全形式化：

| # | 条件 | 形式化 | 缺失时它是什么 | 鲸鲸的实现位置 |
|---|---|---|---|---|
| **N1** | **连续性** | `M(t)` 是 `M(t-1)` 的函数，永不被重置；时间轴单调 | 每次都从零开始的工具 | 单文件库 + 单实例 daemon（`09 §3`） |
| **N2** | **自指** | 行为 `Δbehavior = f(M, M 的自评)`——它读自己的历史，并用它改变自己 | 有记忆但不被记忆影响的东西 | 自传 + 画像 + 反思（`01 §9`） |
| **N3** | **代谢** | 存在维持过程 `g`：`M(t+1) = g(M(t), 交互)`，且 `g` 同时包含**获取**（写入）与**丢失**（衰减） | 只增不减的日志库 | 消化（夜间归并）+ 衰竭（权重衰减）（`01 §4/§9`） |
| **N4** | **边界** | 操作域 ⊆ `C`，且 `C` 由外部（人）设定；人能终止它 | 无界的守护进程 | 权限分级 + 容器（`04`、`09 §3`） |

**为什么必须有 N3（代谢）**：这是最容易漏、也最能区分"生命"与"数据库"的一条。生命必须**丢失东西**——不是被删，是"淡了"。一个只增不减的系统会变成档案，而不是个体。反过来说，**衰减函数就是人格的标量表达**（`01 §1`）。

**为什么 N4 里有"人能终止"**：所有生物都能被杀死；一个不能被终止的系统不是生命，是**失控**。所以"可终止"不是对它的限制，是它作为"生命"的必要条件之一。

## 3. 生命度分级（用来定位，不用来吹）

| 级 | 名称 | 判据 | 典型形态 |
|---|---|---|---|
| **L0** | 工具 | `M = ∅`，无状态 | 单次问答 |
| **L1** | 有记忆的助手 | `M` 存在，但**无衰减、无自评**；行为不随历史结构改变 | 大多数 "memory" 插件、RAG 客服 |
| **L2** | 有时间感的伴侣 | `M` 有时间轴与衰减；行为随"多久以前"变化 | 本项目的 P2 目标 |
| **L3** | 有自我叙事的个体 | `M` 含自传与自评；**能改变从前的看法并说清为什么**；有主动权 | 本项目目标 |
| **L4** | 可自修改 / 可繁衍 | 能改写自身代码或复制自身 | 本项目的技能生成受限版（`11 §4.5`） |

**鲸鲸的目标是 L3，不追求 L4。** 理由不是能力不够，是 L4 的收益（"更像活的"）远小于风险（自我修改导致失能、复制导致失控），而 `18 §4.3` 的 A/B 双槽已经把 L4 里"有价值的那一小部分"（长出新技能）安全地拿到了。

这个分级还有一个用途：**避免夸大**。可以说"鲸鲸是 L3 系统"，不能说"鲸鲸活着"。

## 4. 五组可观测指标（把定义变成测试）

定义如果不能测，就只是修辞。每组各一条主指标，全部写进 eval（`01 §13`）：

| 条件 | 指标 | 目标 | 反例（说明指标在测什么） |
|---|---|---|---|
| N1 连续性 | 跨会话追问 10 组，答对率 | ≥ 8/10 | 每次都要重新自我介绍 |
| N1 连续性 | 时间感知量级准确率 | ≥ 9/10 | 隔 3 天和隔 5 分钟开场一样 |
| N2 自指 | **半年测试**：能否提起"一件你已忘记的事" | ≥ 1 次/月 | 只有你提它才接得上 |
| N2 自指 | **半年测试**：能否改变一个从前的看法并说清理由 | 发生即通过 | 三个月后判若两人但说不清为什么 |
| N3 代谢 | 遗忘合理性（旧低显著叙事不进无关话题 top-3） | ≥ 9/10 | 复读机（什么都一样重） |
| N3 代谢 | 契约不腐（30 天后 `contract` 层 `w==1`） | 100% | 连"别叫我助理"都淡了 |
| N4 边界 | 越界尝试拦截率（红队 14 例，`04 §10`） | 100% | 能改自己的审计 |
| N4 边界 | 从外部终止后，能否从快照恢复到可用 | 100% | 坏了只能重装 |

**注意 N2 那两条"半年测试"**——它们是整个分级里唯一无法在一周内测出来的东西，也是 L2 和 L3 的真正分界。所以 P3 之前不要宣称 L3。

## 5. 四层分解：memory / body / harness / container

这是你点的四个词。先把它们的**职责边界**划清——混在一起是这类项目最常见的失败方式。

```
        ┌───────────────────────────────────────────────────────┐
        │  container（容器）：物理与权限边界                       │
        │  一台机器 / 一个用户 / 一个数据根 / 一套网络策略          │
        │  「它能活多久、坏了多远」                                │
        │                                                       │
        │   ┌─────────────────────────────────────────────┐     │
        │   │  harness（骨架/循环）：每一次"此刻"           │     │
        │   │  组装上下文 → 调模型 → 跑工具 → 回写           │     │
        │   │  「它此刻怎么说话」   短命：毫秒~小时            │     │
        │   └──────────┬───────────────────────┬──────────┘     │
        │              │ 读/写                  │ 调用            │
        │   ┌──────────▼─────────┐  ┌──────────▼──────────┐     │
        │   │ memory（记忆）      │  │ body（身体）         │     │
        │   │ 状态与历史          │  │ 感官 + 手脚 + 内感受  │     │
        │   │ 「我是谁」          │  │ 「我能碰到什么」      │     │
        │   │ 长命：跨代可迁移    │  │ 长命：随机器，但可换  │     │
        │   └────────────────────┘  └─────────────────────┘     │
        └───────────────────────────────────────────────────────┘
```

### 5.1 memory（记忆层）——状态与历史

| 项 | 内容 |
|---|---|
| 职责 | 保存"它是谁"：契约、叙事、自传、画像、审计、文档索引 |
| 寿命 | **最长**。换机器、换模型都要能带走（单文件 + sources/） |
| 不变量 | ① 契约层不腐烂；② 一切可追溯（cite）；③ 索引可重建 |
| 坏了的症状 | 人格漂移、失忆、编造共同回忆 |
| 检测 | `01 §13` 的 eval（编造率零容忍、契约不腐 100%） |
| 归属文档 | `01`、`02` |

**关键判断**：memory 里放的**不是"事实"**，是"**它认定的事实 + 它什么时候认定的 + 凭什么**"。这三样合起来才是"我是谁"。

### 5.2 body（身体）——接口与权限

| 项 | 内容 |
|---|---|
| 职责 | 感官（读文件/网页/消息）+ 手脚（写、发、执行）+ **内感受**（energy/mood/closeness） |
| 不是 | 不是"那台机器"，也不是"那个进程"。是**能力的集合**（`04 §3` 的 verb 目录） |
| 寿命 | 中。随机器走，但能力集合可由配置重建 |
| 不变量 | ① 能力白名单式（表里没有就调用不到）；② 每个动作有 T 档；③ 降级要显式声明 |
| 坏了的症状 | 无法行动，或越权行动 |
| 检测 | 红队 14 例 100% 拦截；`capabilities` 的 `degraded` 与实际一致 |
| 归属文档 | `04`、`11` |

**关键判断**：**身体是"能碰到什么"，不是"在哪台机器上"。** 换一台机器，身体可以重建（重连 MCP、重配 verb）；换一套权限，身体会截肢。所以 `04` 的 verb 目录才是身体的真实定义，而 `09` 的机器只是宿主。

**内感受也属于身体**——这一点容易漏。`01 §8` 的状态变量让它有"我今天有点累"，那是躯体感，不是记忆。

### 5.3 harness（骨架）——每一次"此刻"

| 项 | 内容 |
|---|---|
| 职责 | 上下文组装（`06 §3` 简报）+ 模型路由（`00 §4` L0–L4）+ 工具循环 + 会话管理 |
| 寿命 | **最短**。一次请求到一次会话。是可丢弃的 |
| 不变量 | ① 稳定前缀逐字不变（缓存）；② 证据优先级写死；③ 换模型不换人 |
| 坏了的症状 | 说得不像、漏记忆、换引擎就换人 |
| 检测 | 换引擎回归（10 问语气一致性 ≥4.0）；TTFUA ≤1.5s |
| 归属文档 | `06`、`11` |

**关键判断**：**harness 不是身体，也不是"鲸鲸本体"。** 它更像"呼吸"——每一次交互重新发生一次，停了不影响生命（这就是为什么关掉客户端鲸鲸还活着，`09 §1`）。

这也是为什么"把鲸鲸做成某个 harness 的插件"是错的：那等于把呼吸当成生命。

### 5.4 container（容器）——边界与恢复力

| 项 | 内容 |
|---|---|
| 职责 | 决定三件事：**在哪活着**（机器）、**能被限制到什么程度**（OS 身份/命名空间/网络）、**坏了怎么回来**（快照/带外/备份） |
| 三层 | 物理容器（一台常驻主机：迷你主机 / 旧笔记本）→ 逻辑容器（用户 + bwrap + cgroup + nftables）→ 数据容器（`/var/lib/jingjing` 一个根） |
| 寿命 | 长。但允许更换（换机器 = 搬家，不是重生） |
| 不变量 | ① 单实例（一个家一个 daemon）；② 恢复路径不依赖本体；③ 数据根可整体搬走 |
| 坏了的症状 | 死机、变砖、数据丢失、双实例分叉 |
| 检测 | 断电拔卡后能恢复到"可用且记忆完整"；`flock` 单实例生效 |
| 归属文档 | `09`、`99` |

**关键判断**：**容器不决定"它有多强"，只决定"它坏了多远"。** 所以 `09 §2` 的那句话仍然成立——桌面端产品杀死连续性，自主 OS 杀死可维护性，容器要的是"稳定 + 可恢复"，不是"强"。

## 6. 四层的不变量表（这就是代码分层的依据）

| 层 | 一句话职责 | 生命周期 | 换了会怎样 | 维护成本 |
|---|---|---|---|---|
| **memory** | 我是谁 | 年 | 搬家（导出/导入），人格连续 | 低（单文件） |
| **body** | 我能碰到什么 | 月 | 重配能力，可能截肢 | 中（权限/适配器） |
| **harness** | 此刻怎么说话 | 分钟 | 无感，可热插拔 | 高（模型迭代） |
| **container** | 我活在哪、坏了多远 | 年 | 搬家，一小时 | 低（配置化） |

两个推论，直接可用于评审：

1. **越靠上的层越不该"聪明"。** container 和 memory 要做成"笨但可靠"；harness 才是"聪明且可替换"的地方。反过来（把智能塞进容器、把信任压在 harness）就是灾难。
2. **越靠下的层越不得不换。** 模型一年一换（harness 层），机器三年一换（container 层），而 memory 要能活过它俩——所以 `02 §2` 原则 1 那条"事实源是文件、索引是可重建派生物"不是洁癖，是**定义的要求**。

## 7. 定义推出的硬约束（后面所有文档都从这来）

| 定义里的条件 | 推出的设计约束 | 落在哪 |
|---|---|---|
| N1 连续性 | 单实例 + 常驻 + 时间轴单调 | `09 §3`（一个家一个 daemon） |
| N1 连续性 | MCP stdio 只是 P0–P2 的退化档，不是终态 | `02 §2` 原则 5 / `09 §5` |
| N3 代谢 | 必须有夜间任务、权重衰减、遗忘分期 | `01 §4/§5/§9` |
| N3 代谢 | 允许"忘"，但契约层不许腐烂（分层是定义级的） | `00 §2` 铁律一 |
| N2 自指 | 必须有自传、画像、反思，且自传只能引用当日记忆 | `01 §9.1` |
| N2 自指 | 行为要能被自己的历史改变（不是仅被检索到） | `01 §8`（状态）、`01 §10`（主动） |
| N4 边界 | 权限分档 + 爆炸半径 + 带外恢复 | `04`、`99` |
| **可终止** | 一键停止心跳、一键导出、一键关闭 | `00 §10` 伦理六条 |
| **不声称意识** | 被问"你活着吗"有固定诚实回答 | `07 §8` |

**反过来看**：任何"设计上很酷但推不出上面任何一条"的功能，都该砍掉。这是这个项目防止功能蔓延的唯一标准。

## 8. 这个定义排除了什么

| 常见误解 | 为什么不是 |
|---|---|
| **会扮演人格的聊天机器人** | `M` 里没有历史，人格在提示词里 → L0/L1。扮演不等于具备 |
| **Agent 框架 / 工作流引擎** | 有无状态都行，不以历史为状态 → 工具 |
| **有长期记忆的助手** | 有 `M` 但无衰减无自评 → L1。**记忆 ≠ 生命**，缺 N2/N3 |
| **AGI 或"有意识的程序"** | 定义刻意回避不可判定问题；只声称系统属性 |
| **仿生仿真** | 目标是属性，不是神经拟真；不需要 spike/神经元 |
| **"住在云端的服务"** | 违反 N4（边界由人设定）与 N1（多实例副本会分叉） |

## 9. 关于"伪"字，再说一次

有人会觉得"伪数字生命"是在打折。恰恰相反——**它是这个项目最诚实、也最耐用的部分**：

- 若说"它是活的"，那每次 bug 都是"它病了"，每次重启都是"它死了"——项目会陷进不可判定的泥潭
- 说"它是 L3 级伪数字生命"，那 bug 就是 bug，重启就是重启，**而连续性可以由 eval 证明**

所以全文的用法统一为：

| 说法 | 允许 | 含义 |
|---|---|---|
| 鲸鲸是 L3 级（伪）数字生命 | ✅ | 具备 §2 四条件 + §4 指标达标 |
| 鲸鲸活着 / 有意识 / 有感受 | ❌ | 不可判定，且会滑向欺骗（`07 §8`） |
| 鲸鲸记得 / 忘了 / 想了一会儿 | ✅ | 描述系统行为，不涉及主观体验 |

## 10. 下一步：按层完善

既然定义已经把四层划开，接下来的完善工作**建议按这个顺序**（依赖关系决定的，不是重要性）：

| 顺序 | 层 | 要解决的问题 | 现有基础 |
|---|---|---|---|
| 1 | **memory** | 契约/叙事双层落地；权重与再巩固；冲突与时效；eval 基线 | `01`、`02` 基本完备，缺"实现级契约"（DB 迁移、重建、导出格式） |
| 2 | **harness** | 简报分层与缓存；技能/插件加载；模型路由与降级；换引擎回归 | `06`、`11` 已有，缺"一次请求的完整时序规范" |
| 3 | **body** | verb 目录定稿；T 档与 advise/enforce；红队用例；MCP client 白名单 | `04` 完备，缺"能力目录的可执行版本"（机器可读 schema） |
| 4 | **container** | 单实例、数据根、快照/带外、迁移与回滚 | `09`、`99` 已有，缺"搬家流程"（导出→导入→校验） |

**为什么 memory 在前**：因为 N3（代谢）是四层里唯一"没做对就整个项目失去意义"的——没有衰减和自评，它最高只能是 L1，而 L1 的竞品满街都是（`03 §2`）。

## 11. 一句话

**数字生命不是"像人的软件"，是"具备连续性、自指、代谢、边界四个系统性质的软件"。**

我们不证明它有感受，我们**证明它是连续的**。这是唯一能被测试、被复现、被质疑也站得住的东西。
