# 降级、自动切档、任务编排

> 2026-11-07。三件在一天里做出来的东西，放在一份文档里，因为它们共享同一条原则：
> **能力不够时，先说清楚，再换一种做法** —— 不许假装。

---

## 1. 本地兜底（云端接不上时）

### 触发

`express` 角色的云端模型不可用时：没有 key、key 失效（401）、或调用中途抛错。
判定只有一处：`cloudReady()`（`src/cli/jingjing.ts`）——**有 key 才算云端可用**。

### 两条边界

| 边界 | 做法 | 为什么 |
|---|---|---|
| **上下文一个字不少** | `messages` 原样传给备胎（人格 P1–P4、召回 P10、最近 8/16 轮、环境 P20） | 降级降的是**能力**，不是**记性** |
| **工具一个不给** | `tools: []`，且 `AgentDeps.noTools = true` | 本地 7B 调工具不可靠；给不给都会编 |

### 一致性是硬要求（这条是踩出来的）

> 简报里写着「完全权限：能跑命令」，而调用 `tools: []` —— 模型按简报行事，
> 于是编出一段假的 `npm test` 输出（"25/30 tests passed"，那个测试文件根本不存在）。

所以 `noTools` 必须同时做三件事：

1. `schema` 变成空数组（没有"调用工具"这个动作）；
2. 简报里的权限行改写成「本次没有工具：只能说话」；
3. 关掉 C-1/C-2 两条回路（讨计划、改完自验）——没工具时它们只会让模型把计划念两遍。

三条缺任何一条，都会退化成幻觉。这是**同一个事实必须在两个地方一致**的例子：能力声明与调用参数。

### 可见性（三处留痕）

| 位置 | 内容 |
|---|---|
| 过程面板 | 一条 `notice`：「云端没接到，这条用本地模式答（只能对话，动不了手）」 |
| 顶栏 | 琥珀色「本地 · <模型名>」，悬停说明原因与恢复条件 |
| 数据库 | `meta(express_fallback) = {at, model}` —— 重启后仍在 |

恢复不需要人操作：云端**成功调用一次**（`onUsage` 里 provider ≠ ollama）就删掉标记，顶栏自己变回云端。

### 为什么用 `route/night` 而不是自造 `express@ollama`

隐私闸门里 `express` 被标成「不读记忆原文」。拿它去读召回会得到
`E_PRIVACY: role=express 标记为不读记忆原文，却传来记忆原文`。
本地角色本来就允许读记忆 —— 用它既合法又不用改闸门。

## 2. 自动切档（聊天 / 工作）

### 为什么是规则，不是模型

判成「工作」= 简报从 2600 涨到 5200 tokens。判错就**每轮**多花这些。
所以：规则零成本、可解释、可单测；判不出来时**默认聊天**（宁可漏判，不要误判）。

### 判定顺序（`src/mode.ts`）

1. **没有工具 → 一律聊天**：工作档没工具等于空转，还更贵。
2. **承接语**（"好的/嗯/行/可以"）→ 不翻档，沿用上一轮。
3. **明确的工作信号** → 工作：带命令、带路径/文件名、多步骤、祈使动词 + 宾语。
4. **明确的聊天信号** → 聊天：寒暄、回忆/追问、情绪、问句。
5. **都没有** → 沿用上一轮（粘性）。

粘性比准确率重要：逐句横跳会让预算抖动、语气不一致。

### 三个档位

```
auto（默认）  按每句话判；chip 显示「自动 · 工作」
chat / work  手动固定；chip 显示对应档
```
点一下循环：自动 → 聊天 → 工作 → 自动。每轮回答的 SSE 里带 `mode` 事件，
chip 的后半截跟着真实判定走，不靠前端猜。

## 3. 任务编排（M7 最小切片）

### 形状

```
tasks 表（id / goal / status / steps_json / stalled）
task add|list|show|tick|resume|pause|done|abandon
心跳每 10 分钟顺带推进一步（JJ_TASK_TICK=0 可关）
任务页：写一句目标 → 建；每张卡列出步骤（✓ / ? / ✗ + 验证理由）+ 推进一步 / 挂起 / 放弃
```

### 三条硬规则

| 规则 | 原因 |
|---|---|
| **一次 tick 只推进一步** | 整条计划是幻想：排 12 步，第 2 步偏了，剩下 10 步全是编的 |
| **每步另问一次"达成没有"** | 调用了工具 ≠ 达成了意图 |
| **连续两步无进展 → 挂起去问人** | 不许装作在推进 |

另外两条：步数到顶记 `paused` 而不是 `done`（别假装做完）；模型回不出 JSON 记一步失败（不静默）。

### 实测发现的坑

模型会**原样重试**上一步。修法两层：提示词里点名列出「试过但没达成的动作」；
同签名动作直接短路（记 `E_TASK_REPEAT`），不再花一次执行 + 一次验证。

## 4. 不做什么

- 不引 AIOS 代码（`agiresearch/AIOS` 是 `NOASSERTION`，不能引；`rexleimo/aios` 是 MIT 但假设的是编码 Agent + ContextDB，会和记忆层打架）。
- 不做 DAG / 并行 / 子任务：一次一步 + 验证已经够用，再多就要先证明不是幻觉。
- 不在自动切档里接模型分类：先让规则跑两周，有了"判错几次"的体感再说。
