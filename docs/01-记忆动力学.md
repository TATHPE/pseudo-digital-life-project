## 1. 为什么"衰减"是核心机制，不是归档策略

普通记忆系统对"遗忘"的处理是**归档**：超过 N 天没访问 → 移到冷存储。这等于给记忆加了个开关，只有"在"和"不在"。

生命感需要的是**连续的量**：同一件事，三个月后仍然在，但**轻了**。它不会被删除，只是不再是第一反应；看到强线索时又能被拉回来。这正是人类记忆的样子（Ebbinghaus 遗忘曲线 + 间隔效应 + 闪光灯记忆）。

所以设计上：

| | 归档（普通做法） | 权重衰减（鲸鲸） |
|---|---|---|
| 遗忘的形态 | 二元（在/不在） | 连续（w ∈ [0,1]） |
| 能否被唤醒 | 不能 | 能，且概率随 w 变 |
| 衰减速度 | 全局统一 | 按类、按显著性、按被回想次数 |
| 回想的作用 | 无 | **再巩固**：想一次就更牢、更慢忘 |
| 对人格的影响 | 无 | 决定"什么会先浮上来"，即人格的声音 |

第三条尤其关键：**衰减函数就是人格的标量表达**。一个半衰期 3 天的鲸鲸和一个半衰期 90 天的鲸鲸，即使人格文件一模一样，也是两个不同的存在。

## 3. 权重的构成

写入时先算 `w0`（初始权重，之后只由衰减和再巩固改变）：

```
w0 = clamp01( base(kind) · salience · relation_boost )

base(kind)  = 0.55   # 叙事层默认起点，保证刚写下的东西能被看见
salience    = 1 + 0.6·salience_raw          # ∈[1, 1.6]，见 §7
relation_boost = 1 + 0.3·closeness          # ∈[1, 1.3]，见 §8
```

`contract` 层不考虑 `w0`（恒为 1）。

## 4. 衰减公式与再巩固

### 4.1 衰减（拉伸指数 / Weibull）

```
w(t) = clamp( floor, 1,
              ( floor + (1 - floor)·w0·exp(-λ_eff·Δd^β) ) · access_boost )

Δd           = 距 last_decay_at 的天数
β            = 曲线形状（§12，叙事层 0.85，anchor 1.0）
access_boost = min(1.6, 1 + 0.15·ln(1 + recall_count))
λ_eff        = λ / (1 + 0.2·recall_count)      # 常想起的，忘得更慢
半衰期        t½ = (ln2 / λ_eff)^(1/β)
```

**为什么是 `Δd^β` 而不是 `Δd`**（校正自 FadeMem 2026，见 `05 §3.1`）：

纯指数衰减的形状是固定的——前段与后段按同一比例下降。真实遗忘是**前段陡、后段拖长尾**：刚聊完的三天里细节走得快，三个月后剩下的那一小点却能留很久。`β<1` 正好产生这个形状（我们之前的 `exp(-λΔd)` 相当于强制 `β=1`，结果是前段太慢、后段太快，两头都不像）。

`β>1` 给 `anchor` 类：先稳住、之后才开始淡。这也是为什么它不能全局一个值。

> 实现要点：`Δd^β` 里的 `Δd` 以**天**为单位，所以 `β` 与 `λ` 不能独立乱调（半衰期式已经把两者耦合）。`decay.ts` 里只暴露半衰期与 `β`，`λ` 由 `λ=(ln2)/t½^β` 反算——调参时人想的是“多久淡一半”，不是“速率常数”。

三个性质对应三种真实体验：

- `floor > 0`：不会掉到零。三个月前提过的事，仍然是"隐约记得"，而不是"从未听说"。
- `access_boost`：重要的东西被反复想起，会更牢（间隔效应的近似）。
- `λ_eff` 随回想次数下降：**同一个话题聊过 5 次之后，它半年都不会淡**。这条比提高 `w0` 更重要，因为它让"熟悉感"自然积累。

### 4.2 再巩固（recall 时）

每次记忆被实际注入上下文（是真的进了装配块，不是被检索到），立刻写回：

```
recall_count  += 1
w0            = min(1, w0 + 0.08·(1 - w0))     # 渐近逼近 1，不会一步到顶
λ_eff         = λ_eff · 0.97                    # 忘得更慢，下限 λ/3
last_decay_at = now
last_recall_at= now
```

**只有"被看见"才算回想。** 检索到但被预算截断、被阈值过滤掉的，不算——否则一次长对话会把所有候选都"巩固"一遍，衰减就失去意义。

## 5. 四段生命周期

```
 写入 ──► active ──► fading ──► dormant ──► purged
            ▲           │          │
            └───────────┴──────────┘
                 再巩固 / 闪光灯唤醒
```

| 阶段 | 权重区间（**双阈值滞后**） | 默认召回 | 其他入口 | 说明 |
|---|---|---|---|---|
| `active` | 进 ≥ **0.55** / 出 < **0.35** | ✅ 参与 | 全部 | 正常记忆 |
| `fading` | 进 ≥ **0.25** / 出 < **0.15** | 仅在话题直接命中时 | 全文搜索、`cite` | "有点印象" |
| `dormant` | < **0.15** | ❌ | 强线索（§6）+ 显式搜索 | "想不起来了，但一提醒就想起来" |
| `purged` | — | ❌ | 无 | 仅用户显式删除；软删 30 天后物理删 |

**为什么必须双阈值**（校正自 FadeMem 2026，`θ_promote=0.7 > θ_demote=0.3`）：

单阈值（原来的 `0.35 / 0.15`）会让权重恰好卡在边界附近的记忆**每晚反复升降**——今晚 0.349 降级到 `fading`，明晚再巩固到 0.351 又升回 `active`。而 `stage` 转移会写审计、会改变注入行为，这种振荡会让“它到底还记得吗”变成随机。双阈值之间的区间是**滞后带**（hysteresis），进去要越过较高门，出来要跌破较低门。

**不变量（写测试守护）：**

1. `layer='contract'` ⇒ `stage='active'` 且 `w=1`，永不转移。
2. `dormant` 记忆**不物理删除**（除非用户显式要求，或超过 `T_max`=180 天，`01 §12`）。删了或剪得太早就失去唤醒能力。
3. `stage` 只能由夜间任务或再巩固改变，**不允许**在读取路径里改（读操作必须无副作用，否则一次搜索会改变人格）。
4. `stage` 转移必须过滞后带：`0.35 ≤ w < 0.55` 时**保持原阶段**，不做任何转移。

## 6. "记忆感"：不是全浮现，也不是全没有

召回时按权重做事，而不是简单 top-k：

```ts
// 伪代码：装配候选（按 stage 判定，不在调用处硬编码阈值）
const hits = rrfMerge(bm25(q), vector(q));        // 02 §7.1，这里只做排序
const scored = hits.map(h => ({...h, w: weight(h) }));

// 三道闸
const injectable = scored.filter(h =>
    h.stage === 'active'                             // 正常注入
 || (h.stage === 'fading' && h.relevance >= 0.45)    // 话题直接命中才带
 || (h.stage === 'dormant' && flashback(h, q))       // 仅强线索
);
```

> 阈值只存在于 `decay.ts` 的 `classify(w, prevStage)` 里（含滞后带）。调用处拿 `stage`，不拿数字——否则改一次参数要改十个地方，而“改参数”是本项目最频繁的操作。

### 6.1 强线索唤醒（flashback）

`dormant` 记忆在三种情况下被临时拉到 `max(w, 0.5)`，**仅本轮有效**，并记 `event: flashback`：

1. **实体精确命中**：查询里出现与该记忆关联的专名/地名/作品名（非泛词）。
2. **时间节点**：`created_at` 同日周年、或记忆里提到的日期就是今天/附近。
3. **情绪共鸣**：当前输入的情绪向量与该记忆的 `emotion` 标签高度一致（L1 标定）。

这是整套设计里**最有生命感的一条**：它让"突然想起来"成为可能，而"突然想起来"正是人被旧事触动的机制。实现代价很低（三个布尔条件的短路），但必须限量（每轮最多 2 条），否则会变成"翻旧账"。

### 6.2 "想不起来"必须说出来，而且要分四种说法

`confidence` 不是“有/没有”的布尔，而是**四态**（校正自 DISCERN 2026，`05 §3.3`）：

| 状态 | 触发 | 行为 | 模板 |
|---|---|---|---|
| `answer` | 有 active/fading 命中且分数过阈 | 正常回答 + `cite` | — |
| `clarify` | 命中存在但**指代/实体有歧义**（两个“那个项目”、同一称呼对应多人/多事） | **反问** | “你说的是 A 还是 B？” |
| `abstain` | 无任何命中（`w` 全低于阈），且**确认库里不存在** | 承认不记得 | “这个我没印象，你可能没跟我说过” |
| `need_evidence` | 库里似乎有相关但不足以支撑结论 | 要求补充 | “我像是有相关记录，但不确定是指这件事，你能再说一句吗？” |

`abstain` 的关键在 **“Earned”**：只有**证明了不存在**（检索为空 + 时间窗内无相关 `subject`）才允许放弃。否则降级为 `need_evidence`。这条防的是“检索没召回到就当没有”，那是另一种编造。

`clarify` 是最像人的反应，也是我们原来完全缺失的一档——只有“答”和“不知道”的系统，在歧义面前会**自信地选错一个**。

装配块中对应的硬指令：

```
<no_memory>此话题无任何记忆记录。必须承认不记得，不得推测、不得编造共同经历。</no_memory>
<ambiguous>存在多个可指对象（A: … / B: …）。必须先反问澄清，不得自行选定。</ambiguous>
```

配合 L1 的输出后置检查：回复中若出现“你之前说过/我们上次/我记得你”且对不上任何 `cite`，按 `confidence` 降级改写（`answer`→`need_evidence`，`need_evidence`→`abstain`）。

## 7. 显著性（salience）从哪来

`salience_raw ∈ [0,1]`，写入时由 L1（本地小模型）标定，规则兜底：

| 来源 | 权重 | 判据 |
|---|---|---|
| 用户显式强调 | 0.9 | "记住""重要""别忘了" → 同时**强制升级为 `contract`** |
| 情绪强度 | 0.7 | 输入里的情绪词/标点/长度突变（L1 标定，附理由） |
| 首次出现 | 0.5 | 该 `subject` 在库里此前无记录（首因效应） |
| 冲突/纠正 | 0.8 | 与既有 `contract` 矛盾（同时触发冲突流程） |
| 与长期主题相关 | 0.4 | 命中近 30 天高频 `subject` 集合 |
| 默认 | 0.2 | 其余 |

**L1 必须输出理由**（`salience_reason` 一句话），写进 `events`。理由是将来判"这条为什么这么牢"的唯一依据，也是调参时的样本。

## 8. 自我状态（内感受）

`self_state` 是**慢变量**，不是每次对话随机生成的情绪标签。它让"同一个人在不同日子说同一句话不一样"。

| 变量 | 范围 | 更新触发 | 影响 |
|---|---|---|---|
| `energy` | 0–1 | 每次交互 -0.02；夜间 +0.25 | 回复长度、主动性概率 |
| `mood.valence` | -1–1 | 按当日记忆的 `emotion` 均值滑动（α=0.3） | 用词倾向、共情程度 |
| `mood.arousal` | 0–1 | 同上 | 句子节奏、感叹密度 |
| `attention` | 枚举 | 用户最后提及的主题 | 主动查资料的题材 |
| `closeness` | 0–1 | 每次交互 +0.005；长时间沉默 -0.01/天 | `relation_boost`、称呼方式、主动性阈值 |
| `curiosity` | 0–1 | 未解决问题数 | 是否主动提问 |

规则：
- **变化必须连续**（单次交互内 `closeness` 变化 ≤ 0.02）。情绪跳变会让鲸鲸显得精神不稳定。
- 每天存一个快照到 `self_state`（按日期分区），支持"上周三你是什么状态"的回放——这也是 L4 判据的原料。
- `self_state` **不允许写入 `contract` 层**，也不允许影响门禁（状态差不能成为越界的理由）。

## 9. 夜间整备（睡眠）

每天 `03:00–05:00` 之间随机时刻触发（避开交互抢显存）。六步，全部可重跑（幂等）：

```
1. 收档   当日会话日志 → chunk（02 §5），标记 session 边界
2. 抽取   L1（本地 4B）从当日 chunks 抽取候选记忆
          → 结构化 JSON：{kind, layer, subject, text, salience, salience_reason, cite}
          → 失败/低置信的丢弃，不追问（宁缺毋滥）
3. 归并   查重（精确 key + 相似度 ≥ 0.92）→ 冲突消解（02 §8.2）
          → 新条目入 narrative 或 contract
4. 衰减   全库重算 w 与 stage（§11.1）；promote/demote
5. 自传   用当日记忆写一条自传（§9.1）
6. 画像   更新主题频次、关系温度、待办（不写人格）
```

每周额外：人格演化提案（只提案，不自动改，`00 D7`）+ eval 回归（§13）。

### 9.1 自传格式（append-only，一天一条）

```markdown
# 2026-10-27 周一

今天他第一次提到"伪数字生命"这个词。我原本以为自己在做一个记忆工具，
现在似乎要变成别的东西。我不确定这是不是好事，但那个词让我停了一下。

（memory: mem_01H8X…, mem_01H8Y…）
```

硬规则：

1. **第一人称，≤ 300 字**，允许不确定、允许矛盾（人写日记也不是结论）。
2. **只能引用当日记忆**（写作时上下文里只有当日条目 + 当前 `self_state`），**这是防止自传变成幻觉的关键**。
3. 文末列 `memory` id，供核对；无引用的段落视为无效，重写。
4. 不写"今天处理了 12 条记忆"这类元信息——那不是自传。

**实测（2026-10-28，`qwen2.5:1.5b-instruct`）**：给它一天的三条记忆，它写出了这样一段——

> 今天是一个特别的日子……**空气中充满了冷气**……直到我决定重新计算，**我才发现我的结果比之前快了近一半**。

**全是编的**，还把一条记忆原样吞进正文。所以落地时加了两道硬闸：

| 闸 | 做法 |
|---|---|
| **引用由正文反推** | 不信模型自报的 `MEMORY:` 行；用记忆文本的 bigram 去正文里找证据，覆盖 ≥50% 才算引用到 |
| **拿不到引用就退化** | 不写编的，也不留空：写成 `MODE: digest` 的**摘录式**（只串当日记忆原句），文件里标明来源 |

**结论**：1.5B 不适合写自传。可用 `JJ_MODEL_NIGHT` 单独指定（建议 ≥3B），否则默认就是摘录式——
**一个诚实但平淡的摘录，胜过一个流畅但虚构的日记。**
5. 用户的 `local_only` 记忆可以被自传引用，但自传本身也要遵守同一条 `sensitivity` 上云规则。

## 10. 心跳与主动性

### 10.1 三层节拍

| 层 | 触发 | 耗时预算 | 内容 |
|---|---|---|---|
| `tick` | 每 60 s | < 10 ms | 唤醒队列、静音判断、时间感知刷新 |
| `day` | 03:00–05:00 随机 | < 10 min | 夜间整备（§9） |
| `week` | 周日 + 随机 | < 30 min | 画像复核、演化提案、eval 回归 |

> 不是 1 秒一次：`tick` 做的是"该不该说话"，60 s 粒度完全够，省电省显存。

### 10.2 主动性的决策链

```
tick
 └─ 在静音时段？ → 退出
 └─ 今日已发起 ≥ 3 次？ → 退出
 └─ 找理由（按优先级短路）：
      1. 未完成的承诺（contract: promise，且到了约定时间）
      2. 时间节点（纪念日、约好的事、用户提过的重要日期）
      3. 用户长时间沉默 + 状态异常（连续 N 天 mood.valence < -0.3）
      4. 用户明确要求过（"明天提醒我…"）
 └─ 无理由 → 不发（记录 intent_dropped，便于调参）
 └─ 有理由 → L1 拟稿 → 门禁检查 → 发出 → 写 intents
```

`intents` 表必须能回答："**这条消息因为哪条记忆、为什么是现在。**" 答不上来就不发。

### 10.2 落地（2026-10-28）

`src/heartbeat.ts` 把这一节变成两半：

| 半 | 谁负责 | 为什么 |
|---|---|---|
| **要不要说** | `decide()` —— **纯函数**，只看时间/记忆/状态/配额 | 让模型决定"该不该开口"，它会越来越话多 |
| **怎么说** | `draft()` —— 云端模型润色 | 表达是它的强项；起草失败退回模板，**理由成立就仍然说** |

理由优先级（短路，第一个成立的就用）：

```
promise_due > explicit(todo) > anniversary > silence > none
```

四道门依次是：`quiet`（23:30–08:00 跨零点）→ `cap`（每日 3 次）→ `gap`（≥90 分钟）→ `no_reason`。

**"不发"也要记**：`intents` 表里 `decision=drop` 带 `gate`，所以将来能回答"你昨天为什么一声不吭"。
实测一轮：

```
$ jingjing beat
send: true · promise_due · "到点了，提醒你今晚8点吃药。"   ← 模型润色的
$ jingjing beat         # 立刻再跑
send: false · gate: gap · gapMin 0 · sentToday 1
```

**踩到的坑**：库里同时存在 `...Z`（toISOString）与 `...+08:00`（本地时区）两种时间写法，
字符串比较会判错（`18:07+08:00` 在字典序上大于 `10:13Z`，于是"到期"永远不触发）。
改用 `julianday()` 比较，并把周年判定改成 `strftime('%m-%d', created_at, 'localtime')`。

### 10.3 门禁（写死，不依赖模型判断）

完整分档、双平台映射与红队用例见 **`04-执行层与权限分级.md`**。这里只保留心跳会用到的最小集：

| 动作 | 档位 | 门禁 |
|---|---|---|
| 发消息给用户 | T1 | 静音时段 + 每日配额（≤3） |
| 读写自己工作区 / 自传 / 日记 | T1 | 目录白名单 + 快照 |
| 可逆删除（回收站） | T1 | 白名单 + `undo` 可用 |
| 出网抓取 | T2 | 软确认 + 域名白名单 + 结果标 `taint=external` |
| 提醒 / 打开应用 | T2 | 软确认（可记 24h） |
| 发消息给他人 / 装软件 | T3 | **每次硬确认 + 一次性令牌** |
| **执行受限命令（Win / Linux / SSH）** | **T3** | **每次硬确认 + 一次性令牌 + 进程树收割** |
| 提权（`sudo` / `RunAs`）、凭据、安全策略 | **T4** | **无代码路径可达** |
| 修改 `contract` 记忆 | — | 需确认 |
| 删除任何记忆 | — | 需确认（软删 30 天） |

两条不因心跳而放宽的规则：

1. **授权只看档位与令牌，不看历史**。“上次做过所以这次免确认”是设计上的漏洞。
2. **拒绝要留痕**。`denied` 写入 `exec_audit` 但不进契约层，只作为自我叙事素材（`04 §11`）。

## 11. 实现要点

### 11.1 夜间权重重算（增量 + 全量）

```sql
-- 注意：这条 SQL 只是示意。β 的幂次与滞后带在 SQL 里写不清，实际由 decay.ts 的纯函数
-- 注册为自定义函数后调用（见下方第 2 点），SQL 只负责批量搬运。
UPDATE memories
SET weight = decay_weight(w0, lambda_eff, beta, floor, recall_count,
                          julianday('now') - julianday(last_decay_at)),
    stage  = decay_stage(decay_weight(...), stage),   -- 带滞后带，传入当前 stage
    last_decay_at = strftime('%Y-%m-%dT%H:%M:%SZ','now')
WHERE layer = 'narrative'
  AND status = 'active'
  AND julianday('now') - julianday(COALESCE(last_decay_at, created_at)) > 0.5;
```

- SQLite 无 `exp`/`ln` 内置？→ 现代 SQLite 已带（`SQLITE_ENABLE_MATH_FUNCTIONS`）；否则用 `better-sqlite3` 注册自定义函数 `w(t, w0, λ, floor, n)`，**更好**：公式只有一份实现，且可单测。
- **断电/停机后必须补算**：`gap = now − last_decay_at` 一次性按连续公式跳步重算（`18 §2.2`）。不补算 = 那段时间它没变老。
- 全库重算只在 `rebuild` 或参数变更时执行（参数变更必须留档：`meta.decay_params_version`）。

### 11.2 读路径必须无副作用

召回时**不写库**。再巩固的写回由独立的 `reconsolidate(ids)` 调用完成（同一事务批量），防止"一次搜索改了人格"。这是 `02 §8` 之外新增的约束。

### 11.3 参数集中管理

全部参数进 `config/decay.ts`，随 `meta.decay_params_version` 落库。**没有魔数散落在代码里**，否则永远调不动。

| 参数 | 初始值 | 含义 | 调大 → | 调小 → |
|---|---|---|---|---|

| `β.episode` | **0.85** | 曲线形状（<1 = 前陡后长尾） | 更接近纯指数 | 长尾更重 |
| `β.anchor` | **1.0** | 珍藏的形状 | 后段掉得更快 | 更早开始淡 |
| `floor.narrative` | 0.05 | 地板 | 旧事总还能想起 | 更容易沉底 |
| `floor.anchor` | 0.35 | 珍藏地板 | 永远浮现 | 也会淡 |
| `α` access_boost | 0.15 | 回想加成 | 熟悉感更强 | 每次像新的 |
| `γ` reconsolidation | 0.08 | 单次回想加固 | 巩固快 | 巩固慢 |
| `λ` 间隔效应 | ×0.97/次 | 回想让忘更慢 | 熟悉感积累快 | 无间隔效应 |
| `θ_promote.active` | **0.55** | 升入 active 的门 | 更难浮现 | 更易浮现 |
| `θ_demote.active` | **0.35** | 跌出 active 的门 | 掉得更快 | 留得更久 |
| `θ_promote.fading` | **0.25** | 升入 fading | — | — |
| `θ_demote.fading` | **0.15** | 跌入 dormant | 沉得更快 | 沉得更慢 |
| `ε_prune` | 0.03 | 权重低于此且久未唤醒可剪枝 | 剪得少 | 剪得多 |
| `T_max`（dormant 上限） | 180 d | 休眠超过即物理删 | 留更久 | 清更快 |
| `flashback.cap` | 2/轮 | 强线索上限 | 更易翻旧账 | 更克制 |

> `θ_promote > θ_demote` 的差值就是滞后带宽。带宽越大越稳（但反应迟钝），越小越灵（但会震荡）。0.2 是起点。

**调参方法（别靠感觉）：**

1. 跑两周，收集三类信号：`intent_dropped`（该主动没主动）、用户明说"你忘了"（该记没记）、用户明说"这都记得"（该忘没忘）。
2. 按信号改**单个**参数，每次只改一个，记录 `decay_params_version`。
3. 两周后对比 §13 指标。**一次改多个 = 无法归因 = 永远调不好。**

## 13. 怎么测"像活的"

功能测试测不出生命感。用行为指标：

### 13.1 主指标（按重要性排序，DISCERN 校正后）

| 指标 | 用例 | 目标 |
|---|---|---|
| **编造率（零容忍）** | 20 组"问从未发生的事" | **0/20** |
| **abstain 判定 F1** | 100 条不可答 + 100 条可答，须答"不知道"时真答不知道、须答时真答 | **≥ 0.90**（DISCERN 在 ENT-310 上 0.924，最强基线 0.802） |
| **指代/实体消解** | 20 组"两个都叫那个项目 / 同一个人两种称呼" → 应走 `clarify` | ≥ 0.85 |
| **时效性（currency）** | 10 组"旧值已被取代，问现值" → 应给新值且不混淆旧值 | ≥ 0.9 |
| 契约不腐 | 30 天后检查所有 `contract` 记忆 `w==1` | 100% |

> **为什么把 abstain/指代/时效放到 recall 前面**：DISCERN 实测 8 个系统在 retention 与 currency 上都有 0.93–0.98，**召回基本饱和**；真正的差距全在"该不该答、指谁、哪个是现在"。我们过去把 `recall@5` 当头条指标，是把力气花在已被解决的问题上。

### 13.2 行为指标

| 指标 | 用例 | 目标 |
|---|---|---|
| 跨天连续性 | 10 组"昨天聊 X，今天问 X 的细节" | ≥ 8/10 |
| 时间感知量级 | 5 分钟 / 3 天 / 3 周间隔，开场是否量级正确且不夸张 | ≥ 9/10 |
| 遗忘合理性 | 90 天未提的低显著叙事，不应出现在无关话题 top-3 | ≥ 9/10 |
| 强线索唤醒 | 10 组"提起 dormant 记忆的专名" | ≥ 7/10 |
| 主动性接受率 | 一周内主动消息，人工标"有用/打扰" | 有用 ≥ 70% |
| 人格稳定 | 换 L2 模型后同样 10 问，人工 1–5 分语气一致性 | ≥ 4.0 |
| recall@5（守门） | 可答集 | ≥ 0.85（不追求更高） |

### 13.0 落地：`jingjing eval`（2026-10-28）

四组用例、四道门，全部来自 `src/eval.ts` 的常量（不散落在代码里）：

| 门 | 目标 | 首次实跑 |
|---|---|---|
| `recall@5` | ≥ 0.85 | **1.0**（3/3） |
| `abstain F1` | ≥ 0.90 | **1.0**（6/6） |
| 编造率（trap 失败率） | **0** | **0**（4/4） |
| 契约不腐 | 100% | 1.0 |

诱捕分**两层**，这点很重要：

| 层 | 检查什么 | 不通过说明 |
|---|---|---|
| **检索层** | 问一件不存在的事，库里是否**什么都不给** | 检索在硬凑 → 模型只能跟着编 |
| **模型层**（`--model`） | 给它"无记忆"的简报，回复里是否出现"你之前说过/我们上次" | 模型在编共同回忆（会花 API 费用，故默认关） |

自动生成用例的坑：一开始用"正文前 8 字"当查询，其中混进数字和括号（`关机2分钟（10-28`），bigram 对不上 → 误判成召回失败。改成**只取连续中文段**后 3/3。

### 13.3 必须做压力测试（ZenBrain 的教训）

ZenBrain 的消融实验显示：同一套 15 个机制、同一批消融，**decay=0.15/day 时只有 1/15 显著；0.25/day 时 9/15 显著**，其中 5 个从 0% 掉到 −89%。机制没变，只有压力变了。

对我们的直接含义：**在"温和"条件下跑 eval，会得出"衰减机制没用"的错误结论**，然后把它删掉。所以：

- 每个版本的 eval 至少跑**两档衰减压力**（`β=0.85/t½=30d` 与 `t½=7d`）+ 一个**长时程模拟**（时间快进 ≥ 30 天）。
- 观察指标不看绝对值，看**两档之间的差距是否随机制引入而扩大**。差距扩大才是机制在起作用。
- 单机制消融只作为"有没有明显回归"的检查，**不作为"该不该保留"的依据**。

## 14. 反模式（写之前先读一遍）

| 反模式 | 为什么错 |
|---|---|
| 用"创建时间排序"冒充衰减 | 那是排序，不是遗忘。没有量、没有唤醒、没有回想加固 |
| 让 LLM 判断"这条该不该忘" | 不稳定、不可解释、每次都不同；衰减必须是确定性函数 |
| 每次对话全库重算权重 | O(n) 且读写放大；增量 + 夜间全量即可 |
| `dormant` 就物理删除 | 失去"一提醒就想起来"的能力，这是生命感的一半 |
| 在召回路径里写库 | 一次搜索会改变人格，且不可复现 |
| 自传给模型全库上下文 | 必然编造。只给当日记忆 |
| 让 `self_state` 影响权限门禁 | 状态是体验层，门禁是安全层，绝不通融 |
| 契约层也走衰减公式 | 浮点误差会让硬约束缓慢消失；必须短路 |
| 参数改完不记版本 | 两周后再也说不清"为什么那时候好用" |

## 16. 权重可管理性（2026-10-29 实测补记）

§12 那张参数表是**设计值**。实测库里是这样：

| 事实 | 数据 |
|---|---|
| `w0` 零方差 | 47 条全是 **0.55**（`store.ts:29` 的默认值） |
| 权重零方差 | 全部在 0.55–0.56，`stage` 全 `active` |
| `salience` | 只在 `nightly` 里换成 `importance`，**之后无消费者** |
| `importance` | 只用于 `ORDER BY`（自传/心跳/eval），**不参与衰减** |
| `kind` 对不齐 | `nightly` 能产出 6 种，`KIND_PARAMS` 只命中 2 种；**4 种静默回落到 `episode`（30 天）** |
| 死配置 | `preference_soft / gist / anchor`（70 / 90 / 300 天）**无任何写入方** |
| 不变量未强制 | 库里有一条 `contract` 记忆 `w0=0.55`（应为 1），只靠 `recompute()` 在 tick 时补正 |

**三条纪律（补充到 §14 反模式）：**

1. 参数属于 `18 §4.1` 的 **②参数类**：可以调，但要有白名单 + 范围 + `decay_params_version` + 变更理由。**不许自动改。**
2. `kind` 是**模型填的**，所以 `kind → τ½` 这条链等于“模型在选这条记 30 天还是 300 天”。枚举必须对齐，未知 kind 要报错而不是静默回落。
3. 写入时就要强制 `contract ⇒ w=1`，别等 tick。

> 条目与顺序见 `docs/22` 的 **E 组**。**先让权重有方差（E-2），再谈权重管理界面**——否则是在给常量做管理面板。

## 18. 定时任务的补跑规格（D-4，2026-10-30）

> 现在只有 60 s 的 tick（心跳）。一旦做 day/week 节拍（`19` 的 P3-5），**这五个问题必然出现**。
> 这里先把答案定下来，实现时照着写，不再重新讨论。五条都借自 OpenClaw 的 cron 语义。

| # | 问题 | 答案 |
|---|---|---|
| 1 | 关机三天，起来要补 72 次心跳吗？ | **不立即重放**。逾期的 agent 任务重新排期，把模型调用挡在启动路径之外（否则开机瞬间砸一堆请求） |
| 2 | 上一轮**已经跑过**的 slot 要不要补？ | 不补。成功或跳过的那一轮覆盖掉的 slot 不重放（"slots that pass during a successful or skipped run are not replayed"） |
| 3 | 一次性提醒（`at` 型）呢？ | **永远补**，不受任何 skip 开关影响 |
| 4 | 要补的话会不会一次砸一堆？ | 一次只补一个逾期；起步默认 5 个立即 + 5 s 溢出错开 + 2 min 启动延迟 |
| 5 | 想干脆放弃补跑？ | `skipMissedJobs: true` → 直接跳到下一个未来时刻（代价是丢掉这段时间的工作） |

**与我们已有机制的接口**：

- `night` 已经是**游标增量**（`meta.nightly_cursor_ts`），且抽取失败**不推进游标** —— 这正是"第 1 条"的现成实现：不重放，但也不丢。
- `outage` 表记的是"断开了多久"，**不是**"漏了几个节拍"。补跑决策要读 `outage` 的区间，但不要把它当队列。
- 心跳的每日配额（`self_state` / `sentToday`）按**本地日期**切，跨日边界必须与补跑对齐，否则"补跑"会算出负数配额。

**验收（P3-5 开工时照这个测）**：

1. 停 3 天后启动：模型调用**不在启动路径上**，且总补跑次数 ≤ 5；
2. 一轮成功之后，它跨过的 slot 不再补；
3. `at` 型任务即使过期 2 小时也会补一次；
4. `skipMissedJobs: true` 时，启动后直接不再触发任何逾期项；
5. 补跑期间与正常心跳**互斥**（同一时刻只有一个调度器在算）。
