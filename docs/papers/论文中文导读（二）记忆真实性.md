## 2. 一张图：记忆失真发生在五个位置

这是我从 15 篇里归纳的框架。**"它记错了"是一个太粗的说法**，实际上有五个不同的失败点，对应的修法完全不同：

```
① 写坏      抽取/固化时就把信息弄错了、漏了、编了
             ← TrustMem（2606.25161）
② 存坏      存的时候丢了"这话是谁说的、可不可信"
             ← MemIR（2605.25869）、溯源洗白（2607.29167）
③ 取错      取到了过期的、取到了别人的、没取到就编
             ← Stale/Misattributed/Late（2610.10265）
④ 看错      取对了，但把"前提是假的"当成了真
             ← MemTrace（2606.17328）、TANGLE（2608.13921）
⑤ 说错      以上都对，但嘴上比心里确定
             ← 认知谦逊（2610.12360）、假记忆检测（2609.39473）
```

对鲸鲸的意义：**这五个位置需要五套不同的措施**。我原来在 `00 §11` 写的四条（cite 约束、空记忆硬指令、后置检查、诱捕 eval）只覆盖了 ③ 和 ⑤ 的一部分。

## 3. 逐篇

### 3.1 诊断类：记忆在哪里先坏掉

#### 2610.10265 陈旧、错误归属、或迟到（UC Berkeley）

**问题**：我们评价个人记忆，看的是"最终答案对不对"。但这个分数掩盖了三类在**生成之前**就发生的错误：记忆块里放的是**过期值**、是关于**错误的人**的事实、或者到截止时间**什么都没放进去**。

**做法**：拿"个人事实记忆（PFM）"当参照层，把失败拆成三类分别测量。

**关键数字**：
- 不做"更新解析"时，**70.3% 的提示里会暴露出已被取代的旧值**，而且通常和新值并列摆在一起——模型看到两个值，就自己挑一个。
- 只要**服务时只提供每个槽位的当前值**，陈旧暴露就归零。**所以"陈旧"主要不是检索问题，是记忆构造问题。**
- 更难的是"把修订挂到正确的槽位"：漏合并 → 旧值还活着；错合并 → 当前值被悄悄删掉。四个 LLM 键分配器的键召回更高，但**干净检索率反而更低**。
- 在 LongMemEval 上，开放域的**合并召回从不超过 0.062**（基本是零）。
- **错误归属活过了有效性过滤**：实体后验能降低同名暴露，但在 LoCoMo 上分不开"同名的两个说话人"。
- 延迟方面：检索本身不是瓶颈，**prompt 预填**才是（这条对本地部署很有用）。

**它没解决的**：单人场景/小样本（1,200 条提示是控制的），"槽位"概念要先有人定义 schema。

**对鲸鲸**：这是最该照抄结构的一篇。它证明"我把旧值标成 superseded 了"不够，**必须在服务时只给当前值**，否则模型会在新旧之间随机挑。而我们的 `02 §8.2` 现在是"保留双方并在上下文里同时呈现"——对这个场景是错的（对"不可约冲突"才是对的，见 TANGLE）。

#### 2606.17328 MemTrace：最终准确率掩盖了什么

**问题**：现有评测按"问题行"打分，同一个事实被问 5 次就算 5 次，看不出这个事实**在时间上怎么变**。

**做法**：把**测量单位从"问题"换成"知识点"**（一条关于用户的带类型事实）。每个知识点沿三个维度探：
- **记忆年龄**：这个事实是多少个会话之前出现的
- **问题类型**：当前状态 / 过去状态 / 变化轨迹
- **证据条件**：证据在 / 证据缺失 / **被假前提反驳**

**关键发现**（原文）：系统"很少答对未来从未提到过的事"，而**"当提示里含假前提时，几乎不能正确回答"**——这是跨系统最主要的剩余差距。

**对鲸鲸**：我们的"假记忆诱捕" eval 只测了"问一件从未发生的事"。**漏了"前提是错的"这一类**——比如用户其实用的是 SQLite，模型却问"你把 Postgres 迁移完了吗"，然后被顺着答下去。这类比"从未发生"更隐蔽，因为它看起来像在延续对话。

#### 2608.13921 当个人记忆没有唯一答案（TANGLE）

**问题**：个人记忆里有些冲突**本来就无解**：偏好依赖语境、行为会演化、来源互相矛盾。而现有基准都要求"从冲突证据里恢复出一个答案"，于是奖励了"选一个"，忽略了"这件事本身没有唯一答案"。

**做法**：TANGLE 基准，541 个实例、40 个人格、三类冲突：
- **上下文分区冲突（CPC）**：不同语境下偏好不同，都对
- **行为振荡冲突（BOC）**：偏好随时间来回摆
- **来源矛盾冲突（SCC）**：两个来源直接对立

评的是四件事：**是否识别出"无法确定"、是否保留多个备选、是否主动索取缺失信息、是否选了恰当动作**。两条赛道：给现成记忆的"oracle"和让记忆系统自己抽取的"pipeline"。

**对鲸鲸**：这直接对应我们 `01 §6.2` 新加的 `clarify` 态。它把"应该反问"从工程技巧升级成了一个可测的能力。而且它给了一个重要的提醒：**"压倒性自信地选一个"比"承认没有唯一答案"更糟**——这跟 DISCERN 的结论是同一条。

### 3.2 溯源类：怎么保证"记得的是真的"

#### 2605.25869 MemIR：抑制"溯源角色坍缩"

**问题**：主流架构把历史交互存成**无类型的扁平文本**（摘要、反思、压缩后的上下文）。这导致 **provenance-role collapse（溯源角色坍缩）**——本质上是心理学里的 **source monitoring error（来源监控错误）**：人分不清"我看到的"和"我想到的"，模型分不清"用户说的"和"我总结出来的"。

**做法**：把记忆编译成**带类型的"记忆原子"**，分三种角色：
1. **原始证据**（raw evidence）
2. **检索线索**（retrieval cues）
3. **承载真值的主张**（truth-bearing claims）

**只有被支持的"主张原子"才有事实授权**（factual authorization）。检索时把零散的命中结果重组成"以主张为中心"的证据包。

**数字**：在 LoCoMo 和 BEAM-100K 上稳定优于现有基线，尤其在需要**来源追踪、时间定位、碎片证据聚合**的任务上；历史更长时优势保持。

**它没解决的**：多跳的"跨主张推理"仍然难（它自己承认 LLM-judge 分数上优势较小）。

**对鲸鲸**：这是我们 `02` 的数据模型最该改的地方。我们现在的 `memories.text` 是一句话"认定"，`chunks.text` 是原文——中间少了"这条主张是被哪几条证据支持的"这一层。加了这层，`cite` 才是结构性的，而不是事后拼的。

#### 2608.29606 Agent Zero Memory：三套并行记忆

**问题**：大多数系统只选一种组织方式（事实库 / 向量索引 / 知识图谱），于是继承它的盲区。

**做法**：同一段历史**并行蒸馏成三套**：
1. **情节事件时间线**（episodic events）——把"什么时候"和"什么变了"当一等公民
2. **实体-事件知识图谱**——跨会话连接人和项目
3. **引用锁定（citation-locked）的分层文档记忆（HDM）**——只放持久事实

检索时：先过**意图门**（自包含的话轮不检索、零延迟）→ 来源路由 → 三路并发检索（每路一个工具循环，混合 embedding + 词法）→ 汇总带引用的结果。

**对鲸鲸**：两条马上能用：**（1）"意图门"**——我们缺这个（Oblivion 也提到了同样的角色 `Activator`）。**（2）"引用锁定"作为一层属性**——不是"每个答案都带 cite"，而是"这一层记忆只允许放有引用的内容"。

#### 2607.29167 记忆溯源洗白 —— 我认为这是本次最"没想到"的一篇

**问题**：老式提示注入是"恶意文本留在上下文里"。这篇指出一个更隐蔽的变体：

> **记忆溯源洗白（memory provenance laundering）**：在基于 LLM 的记忆固化过程中，一条**外部观测**（网页、邮件、Slack 消息、工具返回）会被**改写成像是用户历史或工作流偏好的样子**，动作触发条件被保留下来，但"这条信息来自低可信来源"这个边界被**擦掉了**。

关键点：这不是"恶意文本活下来了"，而是**改写让它看起来更有权威了**。现有的提示过滤器、内容消毒、工具守卫都管不了，因为它们都是在"原文"上工作，而洗白发生在**有损压缩（consolidation）之后**。

**做法**：`PPMF`（Provenance-Preserving Memory Firewall）——记忆中间件，**把"记忆有用"和"记忆有授权"解耦**：
- 每条记忆存平台维护的溯源元数据（来源、信任级别、平台、上下文）
- 工具调用前，把**动作风险**与**相关记忆的权威级别**做匹配

**数字**：在固定风险策略的 schema 评测里，**脆弱的合并记忆能到 1.000 的攻击成功率**；保持溯源完整时授权边界成立。

**对鲸鲸**：这篇直接打我们 `01 §9`（夜间抽取）+ `04`（执行层）的结合部。我们的 `taint=external` 是在**摄入时**打的标签，但**夜间抽取会让本地 LLM 把外部文档改写成"一条记忆"**——如果那一刻标签没跟着走，外部内容就变成了"鲸鲸自己的认知"，然后拿它去驱动 T3 工具调用。

正确做法（它的答案）：**溯源元数据不能由模型维护，要由平台（代码）维护**，并且在**动作授权**那一刻才做匹配，而不是在写入时判一次。

#### 2606.25161 TrustMem：给记忆更新加"转移验证器"

**问题**：记忆 agent 会自己生成 write / revise / delete 操作，这些更新可能**遗漏重要信息、破坏已有记忆、引入无支撑的幻觉内容**。而且一旦写进去，就变成**持久的状态错误**，影响之后所有推理。

**做法**：
- **Memory Transition Verifier**：从三个维度评一次更新转移——**覆盖（coverage）、保留（preservation）、忠实（faithfulness）**
- 在同一记忆状态下构造候选更新的**偏好对**，用偏好引导的强化学习直接优化"怎么写记忆"

**数字**：在 MemoryAgentBench / HaluMem / Mem-α 上 SOTA；HaluMem 的记忆抽取 **+12.14 F1**；相比最强基线，转移层面的**遗漏降 40.1%、破坏降 79.1%、幻觉降 50.0%**。

**对鲸鲸**：我们 `01 §9` 的夜间抽取现在只有"成功/失败"两态，没有**质量维度**。它的三维度可以直接搬成三个检查项（尤其"保留"——我们的冲突消解很容易在"新值取代旧值"时把旧值的有用部分一起丢掉）。

#### 2604.11563 Synthius-Mem：抗幻觉的人格记忆

**问题**：所有已发表的 LoCoMo 系统都把对话当成"对原始/轻度摘要对话段做检索"的问题，**没有一个报告对抗鲁棒性**——即"能否拒绝回答用户从未披露过的事实"。

**做法**：不检索"说过什么"，而是**抽取"关于这个人已知什么"**——完整的人格抽取流水线，把记忆组织成关于人的结构化画像。

**数字**（自报）：LoCoMo 上**记忆准确率 94.4%、对抗鲁棒性 99.6%**。

**它没解决的**：单作者公司自报，基准是 LoCoMo；"人格抽取"和我们的"鲸鲸自己的人格"是两件事（它抽的是**用户**的画像）。

**对鲸鲸**：它的"拒绝回答未披露事实"这个指标，就是我们 `01 §13` 里 abstain F1 的同义表述，而且给出了一个可参照的上限数字（99.6%）。

### 3.3 评测类：怎么测出"假记忆"

#### 2609.39473 走出柏拉图的洞穴（FAME）

**问题**：假记忆很难评——它来自智能体的**内部信念**，很容易和"普通的泛化失败"混在一起。而**光看答案往往测不出来**：答案可能对了，但内在信念已经歪了。

**做法**：`FAME`，免训练框架，用**反事实推理下的信念演化**来测假记忆。核心思路：给定反事实场景，看**记忆的潜在概念**在假设干预下怎么漂移；**概念漂移本身**就是"忠实 vs 假记忆"的判别信号。概念可以从**生成答案之前的隐状态**里估计出来（不需要奖励设计、不需要采样多个答案）。

**数字**：AUROC **76.2%–96.7%**；在真实基准上比最强基线高 **3.4%–23.3%**（覆盖 GSM-Symbolic 数学、GitChameleon 代码、BigBench-Hard 复杂推理）；在 BBH "虚假保留" 上比 input-similarity 基线高 58.5%。

**对鲸鲸**：这条给了一个**不用人肉标注**的假记忆检测思路，比我们的"20 组诱捕用例"更可扩展。不过它需要模型隐状态——云端 API 拿不到，只能用在本地 L1 上。所以对我们更现实的用法是：**把"反事实扰动"作为评测用例的生成器**（同一知识点，问"如果是另一种情况呢"），而不必读隐状态。

#### 2610.12360 准确但不谦逊

**问题**：现有 agent 评测只看任务成功率，看不出它**在证据与自身信念冲突时**怎么反应：改答案？承认不确定？还是固执己见？

**做法**：提出**认知谦逊（epistemic humility, EH）**，用三个轨迹级行为维度量化：**识别（Identify）、解决（Solve）、上报（Escalate）**，简称 ISE。在两种知识冲突下评测：受控冲突（参数知识与证据矛盾）和自然冲突（多步执行中两个上下文来源矛盾）。

**关键发现**：**更高的任务准确率并不必然对应更高的认知谦逊**——有些高准确率配置反而更不谦逊。

**对鲸鲸**：这句话值得抄进我们的验收标准。我们 `01 §13` 现在是"准确率 + 编造率"两栏，缺"它在不确定时的**行为轨迹**"。ISE 这个三段式可以直接当验收项：**识别到冲突 → 尝试解决 → 仍然不行就上报（说"我不确定，你确认一下"）**。

### 3.4 攻击类：别人怎么让它记错

#### 2601.05504 记忆投毒的攻击与防御

**背景**：`MINJA`（记忆注入攻击）在理想条件下注入成功率 **>95%、攻击成功率 >70%**。但真实部署里还剩多少、什么防御有效，此前没研究。

**做法**：在**电子健康记录（EHR）agent** 上系统评测，变三个维度：**初始记忆状态、指示提示的数量、检索参数**；模型包括 GPT-4o-mini、Gemini-2.0-Flash 等。

**对鲸鲸**：`04` 里我列的注入威胁是"文档里藏指令"，这篇补上了**通过正常对话逐步植入**这条路径（我们的"抽取通道默认关闭"正好防这个，但它论证了为什么必须默认关）。

#### 2607.15657 智能体会梦见假记忆吗

**问题**：多模态 agent 依赖视觉长期记忆，但**对视觉数据的无条件信任**是个大漏洞。

**做法**：`Lucid`，**黑盒**对抗框架，威胁模型严格限制在"只改图片"：不需要访问目标多模态模型、不需要访问检索编码器、不碰文本通道。制造两种失败：
1. **记忆投毒**（上下文内）：对抗图片替换掉一张普通图片，而先前文本上下文会强化这张图的内容 → 稳定污染视觉回忆，把 agent 引向攻击者选的叙事
2. **记忆注入**（上下文外）：对抗图片替换掉一张普通图片

**对鲸鲸**：鲸鲸第一版不收图，暂时不相关。但它抽象出的一条对我们成立：**"无条件信任某一类输入（图片/截图/剪贴板/网页）"就是攻击面**。`taint` 分级要按**输入类型**分，不只按"本地/外部"分。

### 3.5 人类侧：这件事对人的影响有多大

#### 2408.04681 对话式 AI 放大证人访谈中的假记忆（MIT 等）

**做法**：N=200 的真人实验。被试看一段犯罪视频，然后和四种条件之一交互（控制组 / 问卷 / 预设脚本 chatbot / **LLM 生成式 chatbot**），其中包含 5 个**误导性问题**；当场和一周后各测一次假记忆。

**数字**：
- 生成式 chatbot 条件的假记忆形成**显著增加**：当场的假记忆是控制组的 **3 倍以上**，是问卷组的 **1.7 倍**
- **36.4% 的被试在与生成式 chatbot 交互时被误导**

**对鲸鲸**：这是全批论文里唯一一篇**人是被影响的一方**的研究。对"伪数字生命"这个定位，它比其余 14 篇都重要——见 §5。

#### 2406.04175 虚构的价值（反方观点）

**主张**：不要一刀切地把幻觉当缺陷。作者系统地为"LLM 幻觉/虚构（confabulation）是有价值的资源"做了辩护，并**实证展示**：幻觉输出相比真实输出，**叙述性（narrativity）和语义连贯性更高**——这和人类用"增加叙事性"来做意义建构是同构的。

**对鲸鲸**：这是唯一持相反立场的一篇，但它恰恰解释了**为什么"编造共同回忆"特别难防**：编造的版本往往**比事实更连贯、更像故事、更符合人格**。所以模型不是在"犯错"，它是在优化一个你没让它优化的目标（叙事连贯）。这解释了为什么光靠提示词说"不要编"没用——你得在**结构上**（cite 约束、只授权被支持的 claim）把这条路堵死。

## 4. 五个可以直接用的结论

不改文档，只列出来供你判断（你说过先别动手）：

1. **"记忆块里给什么"比"检索得多准"更决定成败**：70.3% 的陈旧暴露来自"没有做更新解析"，而不是检索误差（2610.10265）。→ 对应我们 `02 §8.2` 的"同时呈现冲突双方"：**对"有明确旧值"的情况是错的**，只该给当前值；只有"不可约冲突"才保留多方。
2. **溯源必须由代码维护，不能由模型维护**（2607.29167）。模型的"整理"本身就是洗白发生的地方，而洗白恰好发生在我们最信任的那一步（夜间抽取）。
3. **记忆要分角色，不能只有一句话**：证据 / 线索 / 主张，只有被支持的 claim 才有事实授权（2605.25869）。
4. **假前提比假事实更难防**（2606.17328）：我们的诱捕用例要加"属性替换"和"错误前提延续"两类。
5. **准确 ≠ 谦逊**（2610.12360）：验收标准要加"识别 / 解决 / 上报"的行为轨迹，而不只是准确率。

## 5. 我认为最该注意的一条：风险是双向的

我之前一直把风险写成"**鲸鲸记错**"。这批论文里有两篇把它翻了过来。

**第一层（2408.04681）**：AI 会**让用户产生假记忆**——3 倍于控制组。这在"助手"场景里是"用户被误导"；但在"伪数字生命"场景里更严重：

> 鲸鲸说："你上次说这个项目你想做到年底，还记得吗？"
> —— 用户没说过。但**语气太笃定、细节太具体、又是"它记得的"**，用户信了，甚至开始按这个"约定"行动。

这是**数字生命定位独有的风险**，所有 14 篇 agent 记忆论文都不测：它们测的是"agent 会不会答错"，不是"agent 会不会**让用户记错**"。而后者对一个每天陪你说话、还会主动开口的东西来说，后果更重——它污染的是**你对你自己历史的记忆**。

**第二层（2406.04175）**：编造之所以难防，是因为它在**优化连贯性**。编出来的版本通常比事实更像故事、更符合人格。所以"限制编造"不能靠语气约束，只能靠**结构**：只有被 cite 支持的 claim 才有资格被说出来。

**工程含义（三条，都很具体）**：
- 我们 `00 §11` 的"输出后置检查"要**双向**：不仅查"它说的事有没有记忆支持"，还要查"它说的事**会不会让用户误以为是共同经历**"。后者是措辞问题（"我记得你说过" vs "如果我没记错，你说过"），但影响很大。
- eval 要加一组**"用户假记忆诱导"**：让鲸鲸在无记忆支持下说一句"我们上次……"，看它是否会这样。目标 0 次。
- `01 §10.2` 的主动性要加一条门禁：**主动消息里不得声称"你之前说过 X"**，除非有 cite。这条比"每日 3 次上限"更防伤害。

4. `2608.13921` TANGLE —— 不可约冲突，和 DISCERN 互补

**术语补充**（在上一份导读的词典之外）：

| 词 | 中文 | 意思 |
|---|---|---|
| provenance | 溯源 | 这条信息**从哪来、谁说的、可信度多少** |
| provenance laundering | 溯源洗白 | 整理时把低可信来源改写成高可信来源的样子，痕迹抹掉 |
| provenance-role collapse | 溯源角色坍缩 | 分不清"原始证据 / 检索线索 / 自己总结的主张" |
| source monitoring | 来源监控 | 认知科学术语，指"我这话是从哪听来的"这种判断能力 |
| confabulation | 虚构 | 无意识地把空缺补成一个连贯但错误的故事（区别于"撒谎"） |
| false premise | 假前提 | 问题本身建立在错误事实上（"你把 Postgres 迁移完了吗"） |
| underdetermination | 不可确定 | 证据不足以唯一确定答案，正确行为是不选 |
| epistemic humility | 认知谦逊 | 愿意识别、处理并表达不确定性 |
| citation-locked | 引用锁定 | 该层记忆**只允许存带引用的内容**，从结构上排除无源内容 |
