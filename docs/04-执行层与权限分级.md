## 0. 结论先行

1. **鲸鲸永远不拼 shell 字符串。** 它调用的是**能力 verb**（`fs.read` / `sys.info` / `fs.trash`），由执行层映射到平台实现。只有 T3 档才允许 `shell.run`，且必须按模板匹配 + 用户确认。
2. **权限分级 T0–T4 是白名单式五档**，不是"开/关"。默认只有 T0 常开，T1 在白名单目录内可自主，T2 需软确认，T3 每次确认，T4 永不开放。
3. **策略判定在执行层，不在模型层。** 模型的任何"我认为这个操作是安全的"都不构成授权。判定只依赖 verb + 参数 + 路径 + 档位，是确定性函数。
4. **删除默认走"回收站"语义（`fs.trash`）；半径 1 内（全权模式）允许真删，但必须先快照。** 铁律三已改为"可恢复或留痕"（`00 §2`、`§4.4`），执行点是快照与审计，不是"不给命令"。
5. **Windows 与 Linux 的差异集中在四个地方**：shell 与编码、路径解析、进程树终止、权限提升模型。抽象层只需要把这四点吃掉，其余能力是薄映射。

## 1. 三层结构

```
        LLM（L1/L2）
           │  只能产生 verb 调用（结构化 JSON），不能产生命令行字符串
           ▼
┌──────────────────────────────────────────────┐
│ ① 能力层（capability）                        │
│    verb 目录 + 参数 schema + 平台实现映射       │
├──────────────────────────────────────────────┤
│ ② 策略层（policy）—— 唯一有权说"不"的地方       │
│    档位 × 路径白名单 × 模板匹配 × 速率 × 确认    │
├──────────────────────────────────────────────┤
│ ③ 宿主层（host）—— 隔离与收尾                   │
│    WindowsHost / LinuxHost                     │
│    降权、Job Object / cgroup、超时、编码、审计   │
└──────────────────────────────────────────────┘
           │
           ▼
   真实文件系统 / 进程 / 网络
```

**为什么三层而不是一层**：能力层决定"能表达什么"，策略层决定"允许到什么程度"，宿主层决定"即使允许也关在笼子里"。三层分开才能在审计里回答"这条命令为什么能跑"——分别对应 `capability`、`policy_rule`、`host_profile` 三个字段。

## 3. 能力目录（verb）

每个 verb 有：参数 schema、默认档位、平台实现、幂等性、超时、输出上限。**LLM 只能看到这张表里的东西。**

| verb | 语义 | Win | Linux | 默认档 | 幂等 |
|---|---|---|---|---|---|
| `fs.list` | 列目录（不递归，软上限 200 条） | `Get-ChildItem -LiteralPath` | `ls -la --` | T0 | ✅ |
| `fs.stat` | 元信息（大小/时间/类型） | `Get-Item` | `stat --` | T0 | ✅ |
| `fs.read` | 读文本，≤ 256 KB，按行截断 | `Get-Content -Raw` | `cat --` | T0 | ✅ |
| `fs.search` | 文件名/内容检索，结果 ≤ 100 条 | `Select-String` | `grep -rIl --` | T0 | ✅ |
| `fs.hash` | sha256 | `Get-FileHash` | `sha256sum` | T0 | ✅ |
| `sys.info` | OS/CPU/内存/磁盘/开机时长/电量 | `CIM` 查询 | `/proc`、`uname -a` | T0 | ✅ |
| `proc.list` | 进程列表（截断） | `Get-Process` | `ps -eo` | T0 | ✅ |
| `fs.write` | 写文件（仅 workspace 白名单内） | `Set-Content -Encoding utf8` | `tee --` / `install` | **T1** | ❌ |
| `fs.mkdir` | 建目录（同上） | `New-Item -ItemType Directory` | `mkdir -p --` | T1 | ✅ |
| `fs.move` | 移动/改名（同白名单） | `Move-Item` | `mv --` | T1 | ❌ |
| `fs.trash` | **可逆删除**（进回收站） | `FileIO.FileSystem::DeleteFile(…, RecycleOption)` | `gio trash --` | **T1** | ❌ |
| `proc.kill` | 终止**自己启动的**子进程 | `Stop-Process` + Job Object | 进程组 `kill -TERM -PGID` | T1 | ✅ |
| `net.fetch` | GET 取文本，域名白名单，≤ 1 MB | `Invoke-WebRequest` | `curl -fsSL` | **T2** | ✅ |
| `msg.notify` | 给当前用户发通知 | Toast / `BurntToast` | `notify-send` | T1 | ❌ |
| `app.open` | 用默认程序打开文件/URL | `Start-Process` | `xdg-open` | T2 | ❌ |
| `shell.run` | 受限命令（二进制白名单 + 参数模板） | `-File` 脚本 / `-Command` 模板 | `execve` + 模板 | **T3** | ❌ |
| `msg.send_other` | 代发消息给他人 | 客户端 API | 同 | **T3** | ❌ |
| `pkg.install` | 装软件 | `winget` | `apt/dnf` | **T3** | ❌ |
| `shell.admin` | 提权执行 | — | `sudo` | **T4 禁止** | — |
| `fs.raw`（无此 verb） | 通配删除、格式化、改 ACL | — | — | **T4 禁止** | — |

**关键取舍**：`rm`、`del`、`sudo`、`reg`、`Set-Acl`、`mkfs`、`dd`、`shutdown`、`net user`、`schtasks`、`systemctl enable` 这些**不提供对应 verb**，因此无法被调用——白名单的强度来自"表里没有"，而不是"表里有但被拦住"。

## 4. 权限分级 T0–T4

| 档 | 名称 | 判定 | 确认 | 超时 | 审计 | 速率 |
|---|---|---|---|---|---|---|
| **T0** | 只读观察 | 无副作用（verb 语义保证） | 不需要 | 10 s | 记事件，不记内容 | 60/min |
| **T1** | 自己空间内可逆 | 路径 ⊆ `workspace/` ∪ `data/` ∪ 临时区 | 不需要（首次软提示） | 60 s | 全量 argv + 路径 + 输出 hash | 30/min |
| **T2** | 外部可逆 | 涉及用户目录、通知、打开应用、出网只读 | **软确认**（可"记住本类 24h"） | 120 s | 全量 + 目标 | 10/min |
| **T3** | 不可逆 / 高影响 | `shell.run`、`pkg.install`、代发消息、白名单目录外写入 | ~~每次硬确认 + 一次性令牌~~ → **2026-11-04 起：过闸门就执行**（见顶部注记） | 300 s | 全量 + 命令原文 | 3/h |
| **T4** | 禁止 | 提权、凭据、安全策略、持久化自启、系统盘批量操作 | 无路径可达 | — | 拒绝并记 `denied` | — |

### 4.0 门禁强度与档位是**两个正交维度**

上表的"确认"一列把两件事混在一起了：**这个动作有多危险（档位）**，和**现在要不要真的拦住它（强度）**。分开之后灵活得多，实际使用中也更接近人的判断：

| 强度 | 行为 | 什么时候用 |
|---|---|---|
| `advise` | **允许执行，但记一条显式告警**到 `exec_audit`，并在回复里说一句"我刚跑了 X，涉及 Y" | 日常主力。多数时候你想**知道**它干了什么，而不是每次都弹窗 |
| `enforce` | 拒绝并等确认（T2 软确认 / T3 一次性令牌） | 上线初期、给不熟的人用、或者刚改过策略 |
| `off` | 该档位整体禁用（等价于把 T3 降成 T4） | 出差、演示、不想被打扰的时段 |

三档强度 × 五档档位 = **按场景收放，而不是重写策略**。这条来自 `dsh-ops` 的 `shellPolicy: advise` + `allowSystemShellFallback` 两个独立开关（见 `D:/DSH/home/profiles/desktop/cordis.yml` 的 `dsh-ops-shell` 行）——它把"建议"和"强制"拆开，比我们原来的五档一刀切更实用。

附带一个同源的设计：`allowSystemShellFallback: false` 表示**不给隐式回退**。对应我们的规则——降级路径必须**显式声明**（`degraded:["no_vector"]` 那种），不允许"本来要用受限 shell，失败了就偷偷用系统 shell"。

### 4.1 一次性能力令牌（防"确认一次，无限复用"）

T2/T3 确认后签发的不是布尔许可，而是绑定死的令牌：

```jsonc
{ "token": "cap_01H9…", "verb": "shell.run",
  "argv_sha256": "…",           // 参数被改一个字节即失效
  "cwd": "D:/LLM/workspace",    // 工作目录锁定
  "paths": ["D:/LLM/workspace/out.csv"],
  "expires_at": "+120s",        // 短时效
  "uses": 1,                    // 单次
  "issued_by": "user", "issued_at": "…" }
```

**为什么必须这样**：否则一次确认会让模型在后续 10 轮里自由执行同类命令（这是所有"确认一次即可"设计的共同漏洞）。

### 4.4 全权模式（`maximalist` profile）——半径 1 内放开

当鲸鲸跑在**它自己的专属设备**上（一台它是唯一主人的机器；x86 迷你主机一类，见 `09 §4.3`），上表整体降一档：**给 root，不给豁免**。

| 原档 | 全权模式下的行为 |
|---|---|
| T0 / T1 | 不变 |
| T2 | 不再软确认，直接执行 + 记录 |
| T3 | **advise**（`§4.0`）+ **执行前自动快照** + 事后一条可回滚记录 |
| T4 | 收窄为唯一一条：**不许删除/篡改自己的审计与备份** |

三条配套（缺一条就不能开全权）：

1. `btrfs`（或 LVM）小时级快照，保留 7 天；`before: [self_modify, pkg, boot, volume]` 强制快照。
2. **带外恢复**：每晚增量到 PC/NAS（不在本机），外加一张可插即活的备份卡 + 你的独立 SSH 公钥。
3. **A/B 双槽部署**：自我修改只在 sandbox 通过冒烟测试后才切槽，失败自动回滚（`18 §4.3`）。

> 一句话：全权模式买的是"**做错事不会死**"，不是"**做错事没人管**"。审计与快照必须比权限更硬，否则不要开这个 profile。

---

### 4.2 越界即降级，不越界即拒

参数里出现白名单外路径 → **不是**"提示一下继续"，而是直接 `denied` 并记录。允许"申请扩权"作为独立动作（用户操作），不做隐式升级。

## 5. 策略引擎

判定顺序（**短路，任一步失败即拒绝**）：

```
1. verb 存在？            → 否：E_NO_CAPABILITY
2. 档位 ≤ 当前会话授权？   → 否：E_NEEDS_CONFIRM（附解释）
3. 参数过 schema？         → 否：E_BAD_INPUT
4. 路径全在允许集内？       → 否：E_PATH_DENIED（记录原始路径）
5. 符号链接解析后仍在集内？  → 否：E_SYMLINK_ESCAPE（防 TOCTOU）
6. 命中硬拒绝模式？         → 是：E_DENIED_PATTERN（并升级告警）
7. 速率/配额未超？          → 否：E_RATE_LIMITED
8. 令牌有效（T2/T3）？      → 否：E_NEEDS_CONFIRM
→ 允许，交给宿主层执行
```

### 5.1 硬拒绝模式（跨平台，正则 + 语义双检）

| 类别 | 例（必须同时覆盖两种 shell 语法） |
|---|---|
| 解释器逃逸 | `-Command` 里出现 `Invoke-Expression`/`iex`、`[scriptblock]::Create`、`bash -c "$(...)"`、`eval` |
| 管道/串联 | `;` `&&` `\|\|` `\|` 后接非白名单二进制、`$()`、反引号、`\n` 注入 |
| 重定向写系统路径 | `>` `>>` `2>` 指向 `/etc`、`/usr`、`C:\Windows`、`%ProgramFiles%` |
| 提权 | `sudo`、`runas`、`Start-Process -Verb RunAs`、`net localgroup administrators` |
| 凭据/密钥 | `~/.ssh`、`%APPDATA%\Microsoft\Credentials`、`*.kdbx`、浏览器 `Login Data`、环境里的 `*_KEY`/`*_TOKEN` |
| 持久化 | `schtasks /create`、`crontab`、`systemctl enable`、注册表 `Run` 键 |
| 破坏性 | `rm -rf /`、`del /s /q C:\`、`format`、`mkfs`、`diskpart`、`shutdown`、`bcdedit` |

**注意**：这张表是**兜底**，不是主防线。主防线是 §3 的"表里没有这个 verb"。字符串黑名单永远可被绕过（编码、`\x` 转义、别名、`$IFS`），所以 T3 的 `shell.run` 还必须叠 §6 的宿主隔离。

### 5.2 `shell.run` 的模板机制

不允许自由拼接。注册的是**完整命令模板**：

```jsonc
{ "id": "git.status", "tier": "T1",
  "win":   ["git", ["status", "--porcelain"]],
  "linux": ["git", ["status", "--porcelain"]],
  "argv_slots": {} }                       // 无参数槽 → 完全确定

{ "id": "python.run_script", "tier": "T3",
  "win":   ["python", ["-X", "utf8", "{script}"]],
  "linux": ["python3", ["-X", "utf8", "{script}"]],
  "argv_slots": { "script": { "pattern": "^[\\w./-]+\\.py$", "must_be_under": "workspace/" } } }
```

参数槽有**正则 + 位置约束**，不是自由文本。T3 的每次调用仍要令牌。


### 5.3 Windows 双栈：5.1 为地板，7 为增强

执行层的 Windows 侧必须能跑在**任一**版本上，否则这套东西绑死在某一台机器上就失去了可移植性。启动时探测一次，之后所有模板走同一条路径：

```ts
type PsFlavor = "pwsh7" | "winps51";

function detect(): { flavor: PsFlavor; exe: string; args: string[] } {
  // 1) PATH 里有 pwsh（winget/scoop/MSI 安装）
  // 2) C:\Program Files\PowerShell\7\pwsh.exe（MSI 默认位置，非 PATH 时兜底）
  // 3) 回退 Windows PowerShell 5.1
  // 全部缺失 → 判为 E_NO_SHELL，禁用所有依赖 shell 的 verb（不影响 T0/T1 的文件类 verb）
}
```

**模板写法规则（写死，不靠人记）**：

| 需求 | 5.1 写法（地板） | 7 的写法（增强） | 说明 |
|---|---|---|---|
| 串联命令 | 分开调用，或用 `;` + `-ErrorAction Stop` | `&&` / `\|\|` | 语义不同（`;` 不看退出码），所以**优先分开调用** |
| 输出编码 | `[Console]::OutputEncoding=[Text.Encoding]::UTF8` + `-Encoding utf8` | 默认 UTF-8 | 5.1 的 `Set-Content` 默认 UTF-16LE，必须显式 `-Encoding utf8` |
| 空值合并 | `if ($null -eq $x) { ... }` | `??` | — |
| 三目 | `if ... else` | `? :` | — |
| 并行 | `ForEach-Object`（串行） | `-Parallel` | 并行度不用在命令层做，交给 Node 侧并发 |
| 执行外部程序退出码 | `$LASTEXITCODE` | 同 + `$PSNativeCommandUseErrorActionPreference` | 5.1 下 `exit $LASTEXITCODE` 显式透传 |

**两条硬约束**：

1. **模板只按 5.1 语法写。** 因为 5.1 能跑的 7 都能跑，反之不成立。7 的语法糖不进模板（`-Parallel` 除外，且必须标 `requires: "pwsh7"`）。
2. **版本写进审计**：`exec_audit.host_profile` 记 `win-local/ps5.1` 或 `win-local/pwsh7`。同一段模板在两版上行为不一致时，这份记录是唯一能定位的东西。

> 这条规则来自一次实测：本机 `pwsh` 不存在（`Get-Command pwsh` 空、PATH 只有 `WindowsPowerShell\v1.0`、无 `C:\Program Files\PowerShell`），而 5.1 下 `echo a && echo b` 直接是解析错误（`&&` 不是此版本的有效语句分隔符）。**"我机器上装了 7" 这种记忆不可靠，探测必须写进代码。**

## 6. 宿主层（隔离）

### 6.1 WindowsHost（默认）

| 机制 | 做法 | 作用 |
|---|---|---|
| 不经 shell | `spawn(bin, argv, { shell: false })` | 消除注入面（**最重要的一条**） |
| 进程树终结 | `Job Object`（`CREATE_SUSPENDED` → 分配 → 恢复），超时 `TerminateJobObject` | 防止 `cmd` 派生的子进程逃逸（`taskkill /T` 不总是够） |
| 降权 | 默认以当前用户 **非提权** 令牌运行；检测到需要提权即 `denied` | 本机 `Fez` 本就非管理员 |
| 低完整性（可选） | 以 `low` 完整性级别启动（`icacls` + 令牌调整） | 限制写入系统位置 |
| 网络 | 默认 `net.fetch` 之外无出站；如需硬隔离，加 Windows 防火墙出站规则按进程 | 防"悄悄上传" |
| 编码 | 环境注入 `PYTHONUTF8=1`、`chcp 65001`、`[Console]::OutputEncoding=UTF8` | 本机 cp936 已实测踩坑 |
| 资源 | Job Object 限制内存上限 + CPU 时间 | 防输出爆炸/死循环 |

### 6.2 LinuxHost

| 机制 | 做法 |
|---|---|
| 专用用户 | `jingjing` 用户，**无 sudo 权限**，家目录只读挂载点 |
| 命名空间 | `bwrap --unshare-all --die-with-parent --ro-bind /usr /usr --tmpfs /tmp --bind $WS $WS` |
| 资源 | cgroup v2：`memory.max`、`pids.max`、`cpu.max`；`ulimit -f` 限制文件大小 |
| 进程终结 | `setsid` 启动，`kill -TERM -PID`（进程组），超时后 `-KILL` |
| 系统调用过滤 | seccomp（`bwrap` 已带基础集），可选 `firejail` 简化 |
| 提权 | 策略层 T4 直接禁止 `sudo`；宿主层不提供 setuid 路径 |

### 6.4 容器（可选增强，P6+）

本机 Docker 已装但引擎未运行，WSL2 在。容器化能统一两端（`docker run --rm --network=none --read-only …`），但引入"引擎在不在"的运行时依赖。**决定：不阻塞任何阶段，作为 T3 的可选加固**——T3 在容器不可用时降级为"直接执行 + 硬确认 + 全量审计"。

## 7. 审计与可回滚

```sql
CREATE TABLE exec_audit (
  id           TEXT PRIMARY KEY,
  ts           TEXT NOT NULL,
  verb         TEXT NOT NULL,
  tier         TEXT NOT NULL,          -- T0..T4
  argv_json    TEXT,                   -- 实际 argv（脱敏后）
  cwd          TEXT,
  host_profile TEXT NOT NULL,          -- win-local | linux-local | ssh:<host>
  policy_rule  TEXT NOT NULL,          -- 命中的白名单规则 id
  capability   TEXT,                   -- 令牌 id（T2/T3）
  exit_code    INTEGER,
  duration_ms  INTEGER,
  stdout_sha   TEXT,
  stdout_head  TEXT,                   -- 前 4KB，超限截断
  truncated    INTEGER NOT NULL DEFAULT 0,
  decision     TEXT NOT NULL,          -- allowed | denied | needs_confirm | timeout
  deny_reason  TEXT                    -- E_PATH_DENIED / E_DENIED_PATTERN …
);
```

- **T1 写操作前快照**：`fs.write/fs.move/fs.trash` 先把原文件复制到 `data/snapshots/<exec_id>/`，保留 7 天 → 提供 `undo(exec_id)`。
- **`fs.trash` 优先于删除**：回收站语义让"删错了"可恢复，这是铁律三在工具层的体现。
- **拒绝也要记**：`denied` 记录比成功记录更有价值——它是"鲸鲸想做什么"的唯一证据。

## 8. 跨平台陷阱（逐条都是实测或已知会出事）

| # | 陷阱 | 表现 | 对策 |
|---|---|---|---|
| 1 | **控制台编码** | 中文输出变 `��Ŀ`（本机 cp936 已复现） | 强制 UTF-8：Windows 注入 `PYTHONUTF8=1` + `chcp 65001`；Linux `LANG=C.UTF-8`；Node 侧 `buf.toString('utf8')` 并校验 |
| 2 | 路径分隔符与盘符 | `D:/a/b` vs `/d/a/b`；UNC `\\srv\share` | 只用 `path.win32/posix` 对应实现；`realpath` 规范化后再判白名单 |
| 3 | 大小写敏感 | Windows 不敏感、Linux 敏感 → 白名单绕过（`C:\WS` vs `c:\ws`） | 比较前统一 `toLowerCase()`（Windows 侧）并比较规范化绝对路径 |
| 4 | 符号链接 / 目录联接 | `workspace/link → C:\Windows` 逃逸 | 解析真实路径后**再**判白名单（`realpath`），并对已存在的父目录逐级校验 |
| 5 | 长路径 | Windows >260 字符失败 | 启用 `\\?\` 前缀或长路径组策略；返回明确错误而非静默截断 |
| 6 | CRLF vs LF | 生成的脚本在对面跑不起来 | 写脚本按目标平台换行；`fs.read` 返回时保留原样但标注 |
| 7 | 退出码语义 | Linux 127/126、Windows 与 PS 的 `$LASTEXITCODE` 都是负数风格 | 显式映射表：127=`command not found`、126=`not executable`；PS 用 `-Command 'exit $LASTEXITCODE'` 透传 |
| 8 | PowerShell 5.1 缺 `&&`、`??`、三目 | 模板在 Win 上语法错（5.1 下 `echo a && echo b` 是解析错误） | 模板一律按 **5.1 语法**写；用 `-File` 执行脚本而非内联（见 §5.3） |
| 9 | 权限位/ACL 丢失 | Linux `chmod +x` 在 Windows 无意义；跨盘复制丢 ACL | `fs.write` 不承诺权限位；需要时用独立 verb 表达（未来 `fs.chmod`，T2） |
| 10 | 输出爆炸 | 递归 `ls` 挂住进程、撑爆内存 | 输出上限 1 MB / 4 K 行，超出即杀 + `truncated=1` |
| 11 | 僵尸/孤儿进程 | 超时后子进程仍在跑 | Job Object / 进程组，`--die-with-parent` |
| 12 | 环境变量泄漏 | `*_API_KEY` 被子进程看到 | `env -i` / 显式环境白名单，只注入必要变量 |
| 13 | TOCTOU | 判白名单后、执行前文件被换成链接 | 宿主层以打开后的 fd 为准（或执行前后双次 `realpath` 比对） |
| 14 | 提权隐形路径 | PS 的 `Start-Process -Verb RunAs` 弹 UAC | 列为硬拒绝模式（§5.1），并监控 UAC 弹窗 |

### 9.5.1 三个坑（都已修，写在这里省得再踩）

1. **`newEnforcer(Model, path)` 不行**：casbin 只接受"文件路径 / 适配器"，内存 Model + 路径混搭会报 `Invalid parameters for enforcer`。改成把模型也落盘（`policy.model.conf`）。
2. **`priority(p.eft) || deny` 需要额外的 priority 字段**，没有它时 deny 规则会静默不匹配（T4 变成"没有规则"而不是"被拒绝"）。改成 deny-overrides，并额外扫一遍 CSV 以区分 `E_DENIED` 与 `E_NO_RULE`。
3. **`normalize()` 挡不住目录联接**：红队第 4 条一开始是"通过"的——因为目标文件不存在，读到 `E_NOT_FOUND` 就当成拦住了。补上真文件后再跑，**泄漏发生了**。
   修法是 `realpathish()`：对最深的已存在祖先做 `realpath`，再把剩余路径接回去。**字符串层面的 `..` 折叠不是安全边界。**

## 14. 会话授权窗口（K-3，2026-10-31 落地）

一次性令牌适合「一次动作一次确认」，但连着做十件小事时，人会退化成只会点确认的机器 ——
那时确认就不再是「在看」，只是「点过」。**授权窗口把「我在看着」说清楚**：限命令、限目录、限时间、可随时收回。

| 约束 | 怎么做 | 为什么 |
| --- | --- | --- |
| 活在进程内存里 | `src/grant.ts` 模块级 Map | 会话级 = 不跨会话继承；落盘就能被偷偷续期 |
| 限命令 | argv[0] 白名单（node/npm/git/python/…） | 窗口不该等于「什么都能跑」 |
| 限目录 | cwd 必须在 scope 内；路径参数不许 `..`/越界 | 范围是唯一的「不会误伤」保证 |
| 限时间 | ttl ≤ 2 小时，到点即失效 | 短期授权比「记住这个决定」安全 |
| 不给密钥 | `sanitizedEnv()`：`*_KEY`/`TOKEN`/`SECRET` 一律不传 | **授权跑命令 ≠ 授权拿钥匙** |
| 逐条审计 | `capability = grant:<id>` | 事后能数：它到底在窗口里跑了什么 |

执行路径没有新增第二条：仍然是 `verbs → execute → policy → audit`，
只是 `execute` 的 T3 分支多问一句「有没有覆盖这条 argv 的窗口」。窗口命中也要过 policy（casbin 照旧）。


### 14.1 完全权限窗口（`--full` / `full: true`）

普通窗口只放行**注册过的模板**；完全权限窗口额外允许 `shell.exec` 跑**任意 argv**。
它不是「绕过权限模型」，而是把同一条路径的一个参数开到最大 —— 逐条审计、policy、审计表全部照旧。

| 维度 | 普通窗口 | 完全权限窗口 |
| --- | --- | --- |
| 命令 | 白名单（node/npm/git/python/…） | 任意命令，**除硬禁名单** |
| 目录 | `scope`（默认 workspace） | 整个 home |
| 时长 | **会话级：不过期**（关掉面板/进程就没了） | 同左 |
| 开窗理由 | 面板一键切：不需要 | 面板一键切：不需要（CLI 建窗口仍要理由） |
| 任意 argv | ✘（`E_GRANT_NEEDS_FULL`） | ✔（`shell.exec`） |
| 密钥环境变量 | 不传 | **仍然不传** |

**永久拒绝的（不可配置，`E_GRANT_FULL_DENY`）**：删除/磁盘/系统配置（`rm` `del` `format` `reg` `sc` `net` `schtasks` `shutdown`…）、
下载器（`curl` `wget` `certutil`…）、壳（`powershell` `cmd` `bash` `wsl`…）。
理由很直接：这三类**任何一类进来，整套闸门就失去意义** —— 一条 `-Command` 就能做任何事。

**两个窗口都拒绝的**：

- **内联求值**（`node -e` / `python -c` / `sh -c` …，`E_GRANT_INLINE_EVAL`）：
  命令必须落在**能读的文件**上，否则审计里只剩一句 `-e`，事后无法回答「它到底跑了什么」。
- **路径越界**（`E_GRANT_PATH`）：绝对路径必须本身就在 home 内，`..` 一律拒。
  完全权限是「在这个家里什么都能做」，不是「什么都能做」。

**可见性**：切到全权时会在 inbox 写一条 `grant_full_open` 事件；输入框旁的 chip 立刻变成「完全权限」。
**一键生效**：取消二次确认与倒计时 —— 安全边界在「哪些命令永久拒绝 + 密钥不传 + 逐条审计」，不在多点几下。
**「会话级」= 活在进程内存里**（`SESSION_ONLY = Infinity`）：不是「15 分钟后过期」，而是「关掉面板/进程就没了」。
再叠一层 15/30 分钟只会让人多点几次，并不会多一层真正的保护（用户原话：「切权限太麻烦还有时间限制，取消掉」）。

> 一句话：**完全权限 = 完全「动手」的权限，不是完全「拿钥匙」的权限。**

### 14.2 权限档与摆放位置（K-3c，2026-10-31）

**位置是设计的一部分**：权限不是「配置项」，是**当前会话的状态** —— 所以它放在输入框左边（composer），
和 DeepSeek Harness 的 permission presets 一致 —— 设置里只放「以后新建会话的默认值」。
把会话级开关塞进设置页，会让人以为改完立刻生效，实际改的只是下一次。

| 档 | 含义 | 怎么实现的 |
| --- | --- | --- |
| `ask` 逐次确认 | 每个 T3 动作都要人点一次（我们原来的默认） | 没有窗口（`currentPreset` 返回 ask） |
| `read` 仅可查看 | 只读；任何要动手的命令都拒 | 一个空白名单窗口 → `E_PRESET_READ_ONLY` |
| `write` 工作区内修改 | 注册过的模板 + workspace，**会话级不过期** | 普通窗口（命令白名单 = `GRANT_COMMANDS`） |
| `full` 完全权限 | 任意 argv + 整个 home，**会话级不过期** | `--full` 窗口（硬禁名单 + 内联求值仍拒） |

三条不变式：

1. **一次只有一个答案**：切档先 `revokeAll`，再开新档 —— 两个窗口并存会让「我现在是什么权限」没有唯一答案。
2. **切到 full 一键生效**（不再手输「我明白」，也没有倒计时）—— 安全感来自
   「哪些命令永久拒绝 + 密钥不进子进程 + 逐条审计」，不来自多点几下；
   `POST /api/permission` 仍会写一条 `grant_full_open` 事件（谁、什么时候、因为什么）。
3. **`/permission <preset>` 带参直接切**（和 DSH 的带参形式一致）；裸 `/permission` 打开选择器。

### 14.3 设置里那一行是什么

设置页的「DEFAULT · 新会话默认权限」只写 `data/config.json` 的 `permission.default`，
**只影响之后新建的会话**；当前会话永远用输入框旁的 chip 切。
这条分界是刻意的：把会话级开关塞进设置页，会让人以为改完立刻生效。

### 14.4 超级权限（super，2026-11-01）

> 「这个权限可以完全接管电脑，也可以随意修改记忆和人格。」—— 用户原话

它和 `full` 不是同一档：`full` 是「在这个家里什么都能做」，`super` 是「连家门的锁也给你」。

| 维度 | 完全权限 `full` | 超级权限 `super` |
| --- | --- | --- |
| 任意 argv | ✔（`shell.exec`） | ✔ |
| 记忆核心（`memory.db` / `persona` / `secrets` / `inbox`） | ✘ 永久拒 | ✔ 能直接改 |
| 硬禁名单（删/关机/装软件/下载/壳） | ✘ 永久拒 | ✔ 放开 |
| 内联求值 `node -e` | ✘ 拒 | ✔ 放开 |
| 出 home 的路径 | ✘ 拒 | ✔ 放开 |
| **格式化磁盘**（`format`/`mkfs`/`diskpart`） | ✘ | ✘（`E_SUPER_STILL_DENY`） |
| **删 `trash/` 或 `snapshots/`** | ✘ | ✘（`E_SUPER_KEEP`） |

**四条硬约束**（`src/supergrant.ts`，都在代码里）：

1. **模型开不了**：只有 `POST /api/super`，且在设置里（人点的按钮）。**2026-11-01 用户定：确认步骤取消** —— 不手输确认词、理由可选。对话里没有这条路径，`taint=external` 的内容更碰不到。
2. **开关留痕**：`data/super.json`（`since` + 理由，没写就记「（没写理由）」）+ inbox 的 `super_grant_open` / `super_grant_close` 事件。
3. **两条永不放开**：格式化磁盘、删回收站/快照 —— 那不是「接管电脑」，是把回滚的底凿沉。
4. **一键收回**，关掉立刻恢复拦截（有测试钉住）。
