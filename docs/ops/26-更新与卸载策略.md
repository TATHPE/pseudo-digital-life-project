# 26 · 更新与卸载策略（P2 产品化）

> 2026-11-14。这份文档定四件事：**要不要自动更新**、**版本怎么查**、
> **卸载会不会删数据**、**发版前过哪些闸**。
> 配套代码：`src/release.ts`、`tools/release.ts`、`tools/uninstall-guard.ts`、
> `tools/bench-baseline.ts`、`CHANGELOG.md`。

## 1. 自动更新：明确不做静默更新

**决策：不做后台静默下载 / 自替换。** 更新策略标识 `manual-verified`，
由用户主动「下载 → 校验 SHA-256 → 覆盖安装」。

为什么（这是产品定位，不是还没做）：

| 风险 | 静默更新会怎样 |
|---|---|
| 一次网络抖动 / 服务端被劫持 | 把用户正在用的版本换成没验过的二进制 |
| 升级过程碰数据目录 | 记忆库、人格六块、DPAPI 密钥一起没 |
| 单机单人、离线优先 | 常驻联网检查本身就是一个额外故障点 |
| 可回滚性 | 后台替换很难给用户一个明确的「回到上一版」按钮 |

`README.md` / `README.zh-CN.md` 的「没有自动更新」因此改成更精确的表述：
**没有静默自动更新，但版本可查、发布物可校验、升级由人确认**。

### 落地的能力

| 能力 | 入口 | 说明 |
|---|---|---|
| 我装的是哪版 | `GET /api/version` | 返回 `version` / `node` / `platform` / `minNode` / `updatePolicy`。只读 `package.json`，不碰 DB、不联网 |
| 六处版本号不漂 | `npm run release:check` | `package.json` / `tauri.conf.json` / `Cargo.toml` / `capabilities.ts` / `mcp.ts` / `README.md`，逐字比对，少一处就红 |
| 发布清单 | `npm run release:manifest` | 构建后生成 `release.json`：版本、时间、每个产物的 SHA-256 与字节数 |
| 下载方可核对 | `npm run release:verify` | 哈希或大小不符 → 判红，别装 |
| 升级没碰数据 | `release:snapshot` → 覆盖安装 → `release:verify-data` | 数据目录逐文件 SHA-256 比对；`memory.db` / `persona` / `secrets` / `inbox` 有增删改即判红，日志 / WAL / `.desk.json` 按白名单忽略 |
| 版本比较（纯函数） | `checkUpdate()` in `src/release.ts` | 只比 semver，**不联网、不下载、不安装**；坏清单降级成「无更新」，不带崩面板 |

`checkUpdate()` 是给未来设置页预留的纯函数，**当前 UI 没有接任何更新检查入口**。
要接的话只允许展示「有新版本 + 去哪下 + 下完该对上哪个哈希」，不许加自动下载。

### 升级流程（发布方 / 用户各做什么）

发布方：改六处版本号 → 更新 `CHANGELOG.md` 与 `docs/ops/release-notes-v<版本>.md`
→ `npm run release:check` → `npm run desktop:sync` → `npm run desktop:sync:check`
→ `npm run desktop:build -- --bundles nsis` → `npm run release:manifest` → 把安装包与 `release.json` 一起发出。

用户：看发布说明 → 下载 → `npm run release:verify` → **退出应用** → 取快照 → 覆盖安装 →
**先别启动应用**，比对通过后再启动：

```bash
npm run release:snapshot -- "D:\Pseudo Digital Life Project\data"
# 覆盖安装（安装目录 D:\Apps\PDLP，与数据目录分开）
npm run release:verify-data -- "D:\Pseudo Digital Life Project\data"
```

快照默认写到当前目录的 `data-snapshot.json`（**别放在安装目录里，会被覆盖安装删掉**），
也可以用第二个参数指定位置：`release:snapshot -- <数据目录> <快照文件>` / `release:verify-data -- <数据目录> <快照文件>`。
比对的是退出应用后到再次启动前这段窗口：此时任何关键数据的变化都不是应用自己写的，只可能来自升级动作。

「数据目录在安装目录之外，覆盖安装不碰它」以前只是文档承诺，现在由指纹比对断言。
升级前后仍建议各导出一次备份（设置 → 工作区域 → 导出备份）。

## 2. 卸载时的数据清理策略

**默认行为：卸载只删安装目录，外部数据目录原样保留。**

| 目录 | 卸载后 |
|---|---|
| `D:\Apps\PDLP\`（安装目录：exe、`app/`、`node/`） | 删除 |
| `D:\Pseudo Digital Life Project\data`（记忆库、人格、inbox、密钥） | **保留** |
| Roaming 里的 `life.pseudolife.desktop` 配置 | 保留 |

要彻底清干净，用应用内的「设置 → 工作区域 → 清空重来」（**会先自动备份**），
不要指望卸载器替你做数据清理。

### 真坑：junction 会被 NSIS 递归删

开发测试版把 `D:\Apps\PDLP\app\src` 做成指向仓库的 Windows 目录 junction
（见 `desktop/DEV.md`）。NSIS 按文件清单卸载时，junction 会被当成普通目录，
**可能顺着链接把 `D:\LLM\jingjing\src` 一起删掉**。

所以卸载前跑一次：

```bash
npm run uninstall:guard -- "D:\Apps\PDLP"
```

它是**只读**的：列出所有链接、检查数据是否被塞进安装目录、给出纯改名的回滚步骤。
- 退出码 `0` = 可以按正常流程卸载；
- `1` = 有链接或内嵌数据，先按输出处理（**别用 `Remove-Item -Recurse` 删 junction**）；
- `2` = 安装目录不存在。

发布侧也守了一道：`npm run release:check` 会检查 `desktop/bundle-src/app` 不含任何链接，
`tools/sync-desktop.ts` 的 `plainPath()` 本身也拒绝链接载荷。

## 3. 性能基线

`npm run bench:baseline` 生成 `docs/ops/perf-baseline.json`，两层分开：

| 层 | 指标 | 用途 |
|---|---|---|
| **闸门（CI）** | `buildBrief` / `estimateTokens` 的 p50/p95 | 跨机器绝对上限（40ms / 5ms），抓数量级退化；`npm run bench:baseline:ci` |
| **观测（本地）** | `shell.log` 里 `start → healthy` 的真实耗时 | 依赖具体机器与开机状态，**不进 CI 闸门**，只供发版前后对照 |

2026-11-14 本机实测：纯函数 p95 分别 `0.15ms` / `0.06ms`；
真实启动 p50 `4s`、p95 `7s`、84 次里 2 次缺 healthy（即开机失败那两次）。
启动修复后的目标是把 p95 压到 2 秒内，且缺 healthy 归零。

正确性评测仍是 `npm run eval:assembly:ci`（召回 / 拒答 / 陷阱 / 预算），性能基线**不替代**它。

## 4. 发布检查清单（发一版过一遍）

```
[ ] npm run check                 typecheck + 全量测试
[ ] npm run map:check             源码地图一致（新增 src/*.ts 要跑 npm run map）
[ ] npm run eval:assembly:ci      装配层评测
[ ] npm run bench:baseline:ci     性能闸门
[ ] npm run release:check         版本六处 + 发布说明 + 快照无链接
[ ] npm run desktop:check         壳与 sidecar 契约
[ ] cargo check / cargo test      Rust 壳（需 MSVC 工具链）
[ ] npm run desktop:sync && npm run desktop:sync:check
[ ] npm run desktop:build -- --bundles nsis
[ ] npm run release:manifest      生成 release.json
[ ] npm run release:verify        校验产物
[ ] 装一遍再验；装前跑 npm run uninstall:guard
[ ] 升级演练：release:snapshot → 覆盖安装 → release:verify-data 全绿
[ ] 写 docs/ops/release-notes-v<版本>.md 与 CHANGELOG.md
```

注意：`desktop:sync` 每次会在 `desktop/bundle-src/` 留一个 `.stage-*-previous` 旧快照
（本机批量删除保护会拦下脚本里的 `rmSync`）。跑完确认有效载荷后，手工清掉这些备份
再提交/打包，否则会像 2026-11-14 那样堆到 500MB+。

## 5. 明确还没做的

- 签名密钥 + Tauri updater endpoint（要发布基础设施，短期不引入）。
- **覆盖安装后的整机回退**：`npm run rollback-e2e` 验的是应用层 A/B 槽（人格 / 技能）的自动回滚，
  不是把整个安装包退回上一版。「升级别改到数据」已由 `release:snapshot` / `release:verify-data` 覆盖，
  但整机回退仍靠人从备份恢复。
- Linux CI 真机、WSL 真机验收；真·干净机器上的 `jingjing setup`（`setup:e2e` 是模拟 runner）。
